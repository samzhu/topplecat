# ToppleCat 0.0.2 Release Documentation Design

## Purpose

Prepare an accurate, bilingual release-documentation set for the completed
0.0.2 core-correctness work. The repository has not been tagged, pushed, or
published to Maven Central, so the documentation must describe 0.0.2 as a
release candidate / release preparation and must not claim that a remote
artifact is available.

## Deliverables

1. Add `docs/releases/0.0.2.md` in English and
   `docs/releases/0.0.2.zh-TW.md` in Traditional Chinese.
2. Link both release notes from the corresponding root README documentation
   lists.
3. Update release-facing language in `README.md`, `README.zh-TW.md`, and
   `docs/guide/getting-started.md` so it distinguishes local source-checkout
   validation from a future Maven Central publication.
4. Add concise cross-references in the authoring and verification guides to
   the release notes where that gives readers version-specific context.

## Release-note Content

Each language version will contain the same five sections:

- **Status and compatibility:** Version 0.0.2 is prepared but not remotely
  published; Java 25 and the documented Gradle baseline remain required; no
  public evidence or `agent-feedback.json` schema changes are introduced.
- **Expected-value correctness:** A top-level `expected` key counts only when
  `ToppleCase.verify(...)` asserts it. Reading through `expected(...)` no
  longer satisfies enforcement. This prevents a green test from treating
  deserialization as proof.
- **JSON numeric correctness:** Recursive comparison uses exact mathematical
  numeric equality, so `200`, `200.0`, and `200.00` compare equal, including
  in nested objects and arrays, while structural differences continue to fail.
- **Reviewer escrow update:** Authorized reviewers can restore, edit, check,
  review, and run `toppleCatUpdateEscrow`. The task stages and validates the
  revised reviewer source, writes reviewer-local metadata-only audit counts,
  activates atomically, retains the old custody state until activation, and
  safely recovers on failure. Ordinary `toppleCatHide` still rejects changed
  restored source.
- **Public-contract mutation scope:** Default PIT is explicitly limited to
  `sourceSets.test`; reviewer rows and reviewer-only JUnit tests remain a
  separate retest safeguard and cannot inflate the public mutation score.

The notes will also state the verification evidence: targeted functional tests,
the full Gradle check, and `scripts/verify-release.sh` completed successfully.
They will not expose reviewer values, identifiers, paths, source names, or raw
failures.

## README and Guide Changes

The README installation section will retain the intended `0.0.2` coordinates
as the upcoming release coordinates, but will label them as pending remote
publication. It will point source-checkout contributors to
`publishToMavenLocal` and clearly state that this is local validation rather
than publication. The documentation index will link to the release note in its
matching language.

The getting-started guide will make the same publication-status distinction.
The authoring guide will link readers to the numeric and expected-consumption
release details. The verification guide will link readers to the escrow-update
and PIT-boundary release details. These guides remain normative for workflow;
the release note is explanatory and version-specific.

## Boundaries and Verification

- Do not modify production code, test code, public evidence schemas, or safe
  feedback schemas.
- Do not tag, push, create a pull request, or publish remotely.
- Do not add reviewer-only data to public documentation.
- Validate Markdown with `python3 scripts/verify-docs.py` and inspect the
  final diff for consistency between English and Traditional Chinese content.
