# PIT Mutation Testing 研究 findings

> 研究範圍：只使用 [PIT 官方網站](https://pitest.org/)、[PIT 官方 GitHub repository](https://github.com/hcoles/pitest) 的原始碼與測試；Mutation Testing 的學術背景另列一篇正式出版的 survey。本文描述 PIT 本身，不是 ToppleCat 的已實作行為，也不替 ToppleCat 推導產品規則。

## 先說結論

- PIT 的正常語意是「一次一個 mutant」：每個 `MutationIdentifier` 會被重新產生為一份 mutated class bytecode，載入後執行，得到自己的結果；多個 mutant 可以被分組到同一個 mutation unit／minion，但 worker 仍在 `for` 迴圈中逐一 hot-swap、reset、執行與回報。證據是 [PIT 官方基本概念](https://pitest.org/quickstart/basic_concepts/)、[`MutationTestWorker`](https://github.com/hcoles/pitest/blob/fcb9adc815ff7dbacbe91c65972a05f9a1ffb960/pitest/src/main/java/org/pitest/mutationtest/execute/MutationTestWorker.java) 與 [`MutationTestUnit`](https://github.com/hcoles/pitest/blob/fcb9adc815ff7dbacbe91c65972a05f9a1ffb960/pitest-entry/src/main/java/org/pitest/mutationtest/build/MutationTestUnit.java)。
- PIT 變異的是 compiler 產生的 JVM bytecode，不是重寫 Java source；source-level 例子只是便於說明同一個 bytecode 變化。[官方 mutators 文件](https://pitest.org/quickstart/mutators/) 與 [`GregorMutater`](https://github.com/hcoles/pitest/blob/fcb9adc815ff7dbacbe91c65972a05f9a1ffb960/pitest/src/main/java/org/pitest/mutationtest/engine/gregor/GregorMutater.java) 都直接支持這一點。
- mutant 數量沒有固定常數或「每行一個」規則；它取決於目標 class、選用的 mutators、bytecode 中實際匹配的 mutation points，以及 PIT 的 mutation/project filters。coverage 主要用來挑選要跑的 tests；它可令結果成為 `NO_COVERAGE`，但不是用來把每個 mutation point 變成固定數量。[`MutationSource`](https://github.com/hcoles/pitest/blob/fcb9adc815ff7dbacbe91c65972a05f9a1ffb960/pitest-entry/src/main/java/org/pitest/mutationtest/build/MutationSource.java)、[`MutationTestBuilder`](https://github.com/hcoles/pitest/blob/fcb9adc815ff7dbacbe91c65972a05f9a1ffb960/pitest-entry/src/main/java/org/pitest/mutationtest/build/MutationTestBuilder.java)、[`MutationContext`](https://github.com/hcoles/pitest/blob/fcb9adc815ff7dbacbe91c65972a05f9a1ffb960/pitest/src/main/java/org/pitest/mutationtest/engine/gregor/MethodMutationContext.java) 是直接證據。
- operator 刻意改變的是程式／bytecode semantics；這不等於一定產生無效 class。若 mutated class 無法載入，PIT 把該次結果記成 `NON_VIABLE`；這是執行結果，不是另一套 operator。[`DetectionStatus`](https://github.com/hcoles/pitest/blob/fcb9adc815ff7dbacbe91f9a1ffb960/pitest/src/main/java/org/pitest/mutationtest/DetectionStatus.java) 與 [官方結果說明](https://pitest.org/quickstart/basic_concepts/) 有明確區分。

## 1. 是一次全部套用，還是逐個 mutant 執行？

### 正常答案：逐個 mutant 執行

PIT 先掃描 class bytecode，產生 `MutationDetails` 清單；之後 `getMutation(id)` 只對指定的 `MutationIdentifier` 產生一個 `Mutant`，其中包含該 mutation 的 details 與 mutated class bytes。[`Mutater`](https://github.com/hcoles/pitest/blob/fcb9adc815ff7dbacbe91c65972a05f9a1ffb960/pitest/src/main/java/org/pitest/mutationtest/engine/Mutater.java)、[`GregorMutater.getMutation`](https://github.com/hcoles/pitest/blob/fcb9adc815ff7dbacbe91c65972a05f9a1ffb960/pitest/src/main/java/org/pitest/mutationtest/engine/gregor/GregorMutater.java)。

一個 mutation unit 可能包含一批 `MutationDetails`，甚至可由多個執行緒並行處理 unit；但每個 minion 內的 worker 是：

1. 取一個 mutation。
2. 針對它產生 mutated bytes。
3. reset environment。
4. 用 `HotSwap` 把該 class 放入 JVM。
5. 執行該 mutation 的 covering tests。
6. 回報這一個 mutation 的 `MutationStatusTestPair`。

這個順序直接出現在 [`MutationTestWorker.run` 與 `processMutation`](https://github.com/hcoles/pitest/blob/fcb9adc815ff7dbacbe91c65972a05f9a1ffb960/pitest/src/main/java/org/pitest/mutationtest/execute/MutationTestWorker.java)。外層 [`MutationAnalysisExecutor`](https://github.com/hcoles/pitest/blob/fcb9adc815ff7dbacbe91c65972a05f9a1ffb960/pitest-entry/src/main/java/org/pitest/mutationtest/execute/MutationAnalysisExecutor.java) 只負責提交 analysis units；它不是把所有 mutants 疊在同一份 class 上。

所以，以下兩句要分開理解：

- 「一批 mutants 共用一個 forked minion／mutation unit」：可以。
- 「同一個測試執行中把多個 mutant 同時套用」：一般不是；每次測試看到的是當前那一個 mutant，之後 PIT reset，再處理下一個。

### 執行哪些 tests

PIT 先做一般 line coverage，再根據 coverage 與 test timing 為每個 mutation 指派、排序相關 tests；`MutationSource` 在建立 `MutationDetails` 後呼叫 `assignTestsToMutations`。[官方基本概念](https://pitest.org/quickstart/basic_concepts/)、[`MutationCoverage`](https://github.com/hcoles/pitest/blob/fcb9adc815ff7dbacbe91c65972a05f9a1ffb960/pitest-entry/src/main/java/org/pitest/mutationtest/tooling/MutationCoverage.java)、[`MutationSource`](https://github.com/hcoles/pitest/blob/fcb9adc815ff7dbacbe91c65972a05f9a1ffb960/pitest-entry/src/main/java/org/pitest/mutationtest/build/MutationSource.java)。

預設不是把所有 tests 都跑完才決定：`MutationTestWorker` 在非 full-matrix 模式使用 early-exit test group，第一個 failure 即足以判定 `KILLED`；full mutation matrix 才會記錄所有 succeeding tests 與 killing tests。[`MutationTestWorker.doTestsDetectMutation`](https://github.com/hcoles/pitest/blob/fcb9adc815ff7dbacbe91c65972a05f9a1ffb960/pitest/src/main/java/org/pitest/mutationtest/execute/MutationTestWorker.java)、[`MutationStatusTestPair`](https://github.com/hcoles/pitest/blob/fcb9adc815ff7dbacbe91c65972a05f9a1ffb960/pitest/src/main/java/org/pitest/mutationtest/MutationStatusTestPair.java)。

### 唯一需要特別說明的「多個 bytecode point 同時變」例外

PIT 的 `detectInlinedCode` 針對 compiler 為 `finally` 等語意複製出的 inlined code，可以把同一 line、同一 mutator／description 的多個 mutation details 合併成一個 `MutationDetails`，其 `MutationIdentifier` 含多個 instruction indexes；該 mutant 會一起改那些複製點。這仍是一個獨立 mutant 的一次執行，不是把任意不同 mutants 任意疊加。[`InlinedFinallyBlockFilter`](https://github.com/hcoles/pitest/blob/fcb9adc815ff7dbacbe91c65972a05f9a1ffb960/pitest-entry/src/main/java/org/pitest/mutationtest/build/intercept/javafeatures/InlinedFinallyBlockFilter.java)、[`MutationIdentifier`](https://github.com/hcoles/pitest/blob/fcb9adc815ff7dbacbe91c65972a05f9a1ffb960/pitest/src/main/java/org/pitest/mutationtest/engine/MutationIdentifier.java)；官方 command-line 文件也說明 inlined-code detection 可能建立一個同時影響多個 instruction 的 mutation。

### PIT 官方結果狀態

`DetectionStatus.isDetected()` 是 PIT 對 status 的原始分類；下表保留官方名稱，不把它們改寫成 ToppleCat 的 verdict。

| 狀態 | PIT source 中的實際意義 |
| --- | --- |
| `KILLED` | covering test 在 mutant 存在時失敗；PIT 的 `CheckTestHasFailedResultListener.status()` 只要有 failure 就回傳它。 |
| `SURVIVED` | covering tests 都沒有失敗；mutation 沒被 test suite 偵測到。 |
| `NO_COVERAGE` | 沒有任何 test 覆蓋 mutation；PIT 會在 status map 中標記。官方文件說它和未被偵測相似，但區別是根本沒有 covering test。 |
| `TIMED_OUT` | mutation 執行超時；可能是 mutation 造成無限迴圈，但 PIT 不宣稱一定如此。 |
| `NON_VIABLE` | mutated class 無法載入 JVM；`MutationTestWorker` 在 `HotSwap.insertClass` 失敗時標記。 |
| `MEMORY_ERROR` | 處理 mutation 的 JVM 發生 out-of-memory。 |
| `RUN_ERROR` | 執行 mutation 時發生未被更精確分類的錯誤，或 minion 非正常退出。 |
| `EQUIVALENT` | source enum 定義為與未變異程式等價；PIT 將它視為 detected，但「等價」本身不是測試偵測到的行為。 |
| `NOT_STARTED`、`STARTED` | 內部生命週期狀態，分別表示尚未評估、已開始但尚未完成；不是最終 mutation outcome。 |

上述定義來自 [`DetectionStatus`](https://github.com/hcoles/pitest/blob/fcb9adc815ff7dbacbe91c65972a05f9a1ffb960/pitest/src/main/java/org/pitest/mutationtest/DetectionStatus.java)、[`MutationStatusMap`](https://github.com/hcoles/pitest/blob/fcb9adc815ff7dbacbe91c65972a05f9a1ffb960/pitest-entry/src/main/java/org/pitest/mutationtest/MutationStatusMap.java)、[`CheckTestHasFailedResultListener`](https://github.com/hcoles/pitest/blob/fcb9adc815ff7dbacbe91c65972a05f9a1ffb960/pitest/src/main/java/org/pitest/mutationtest/execute/CheckTestHasFailedResultListener.java) 與 [PIT 官方基本概念的 outcome 說明](https://pitest.org/quickstart/basic_concepts/)。官方基本概念頁列出使用者最常見的七類結果；source 另外保留 `EQUIVALENT` 及兩個內部狀態，故本表不省略它們。

## 3. mutant 數量如何決定

### 不是固定數量，也不是單純按 source 行數

可以把候選數量抽象成：

`可變異的目標 class／method × 啟用的 mutator × 該 mutator 在編譯後 bytecode 中實際匹配的 mutation points`，再經過 PIT 的 interceptors、project filters 與可能的 inlined-code consolidation。

每個 operator 的 visitor 在看到可變異 bytecode 時註冊一個 `MutationIdentifier`；id 由 method location、instruction index（或 inlined 時的 indexes）與 mutator identity 組成。因此同一 source line 可能有零個、一個或多個 mutants；同一 bytecode point 也可能被不同啟用 operator 各自產生候選。[`MethodMutationContext`](https://github.com/hcoles/pitest/blob/fcb9adc815ff7dbacbe91c65972a05f9a1ffb960/pitest/src/main/java/org/pitest/mutationtest/engine/gregor/MethodMutationContext.java)、[`MutationIdentifier`](https://github.com/hcoles/pitest/blob/fcb9adc815ff7dbacbe91c65972a05f9a1ffb960/pitest/src/main/java/org/pitest/mutationtest/engine/MutationIdentifier.java)。

數量受到下列因素共同決定：

1. **目標範圍**：PIT 只對 `CodeSource.getCodeUnderTestNames()` 中的 classes 建立 mutation units；class/method exclusions 也會減少候選。[`MutationCoverage`](https://github.com/hcoles/pitest/blob/fcb9adc815ff7dbacbe91c65972a05f9a1ffb960/pitest-entry/src/main/java/org/pitest/mutationtest/tooling/MutationCoverage.java)、[`GregorEngineFactory`](https://github.com/hcoles/pitest/blob/fcb9adc815ff7dbacbe91c65972a05f9a1ffb960/pitest/src/main/java/org/pitest/mutationtest/engine/gregor/config/GregorEngineFactory.java)。
2. **mutator 設定**：未指定時使用 `newDefaults()`；指定 `mutators` 時用指定的名稱／群組，`ALL` 會展開目前 service registry 中的所有 mutators。[`Mutator`](https://github.com/hcoles/pitest/blob/fcb9adc815ff7dbacbe91c65972a05f9a1ffb960/pitest/src/main/java/org/pitest/mutationtest/engine/gregor/config/Mutator.java)。
3. **實際 bytecode 形狀**：例如 `INCREMENTS` 只看到 JVM `IINC`；Java member-field `i++` 通常由 `MATH` 處理，因 compiler 不使用 local-variable 專用的 `IINC`。[`IncrementsMutator`](https://github.com/hcoles/pitest/blob/fcb9adc815ff7dbacbe91c65972a05f9a1ffb960/pitest/src/main/java/org/pitest/mutationtest/engine/gregor/mutators/IncrementsMutator.java)、[官方 mutators 文件](https://pitest.org/quickstart/mutators/)。
4. **filters／合併**：mutation interceptors 和 project filters 可移除或改寫候選；`detectInlinedCode` 可能將 compiler-inlined `finally` 的多個 details 合為一個帶多 instruction indexes 的 mutant。[`MutationTestBuilder`](https://github.com/hcoles/pitest/blob/fcb9adc815ff7dbacbe91c65972a05f9a1ffb960/pitest-entry/src/main/java/org/pitest/mutationtest/build/MutationTestBuilder.java)、[`InlinedFinallyBlockFilter`](https://github.com/hcoles/pitest/blob/fcb9adc815ff7dbacbe91c65972a05f9a1ffb960/pitest-entry/src/main/java/org/pitest/mutationtest/build/intercept/javafeatures/InlinedFinallyBlockFilter.java)。
5. **coverage 與 history 的角色不同**：coverage 會把 covering tests 指派給 mutation，沒有 covering test 的候選最後是 `NO_COVERAGE`；incremental history 可以重用已知結果、改變本次要實際處理的 workload，但不是 mutation operator 的候選生成規則。[`MutationSource`](https://github.com/hcoles/pitest/blob/fcb9adc815ff7dbacbe91c65972a05f9a1ffb960/pitest-entry/src/main/java/org/pitest/mutationtest/build/MutationSource.java)、[`MutationTestBuilder`](https://github.com/hcoles/pitest/blob/fcb9adc815ff7dbacbe91c65972a05f9a1ffb960/pitest-entry/src/main/java/org/pitest/mutationtest/build/MutationTestBuilder.java)、[PIT incremental analysis 文件](https://pitest.org/quickstart/incremental_analysis/)。

`numberOfThreads`、`mutationUnitSize` 與 grouping 主要改變平行化／封裝方式，不把一個 unit 內的 mutants 變成 higher-order mutant；執行仍由 worker 對 range 中的每個 mutation 逐項處理。[`MutationGrouper`](https://github.com/hcoles/pitest/blob/fcb9adc815ff7dbacbe91c65972a05f9a1ffb960/pitest-entry/src/main/java/org/pitest/mutationtest/build/MutationGrouper.java)、[`MutationTestWorker`](https://github.com/hcoles/pitest/blob/fcb9adc815ff7dbacbe91c65972a05f9a1ffb960/pitest/src/main/java/org/pitest/mutationtest/execute/MutationTestWorker.java)。

## 4. 官方 mutation operators：逐項實際程式意義

下表的「實際意義」是把 operator source 中的 opcode／method replacement 翻成 Java 程式語意；它不是說 PIT 真的先產生 Java source 再編譯。每一列都附 source implementation 與官方 JUnit test。`Active by default` 以官方文件／目前 Gregor default configuration 為準；`Optional`／`Experimental` 不會因為存在於 source 就自動啟用。

### Default／stable operator set

| 官方 operator name | 實際改變的語意 | 狀態與核對 |
| --- | --- | --- |

### 文件與目前 source 的版本差異

官方 mutators 文件仍保留 `RETURN_VALS` 的歷史說明，並列出一些舊／額外 mutation families；目前這個 source snapshot 的 service registration 沒有 `RETURN_VALS` factory，default code 改用 `TRUE_RETURNS`、`FALSE_RETURNS`、`PRIMITIVE_RETURNS`、`EMPTY_RETURNS`、`NULL_RETURNS`。同樣地，`INLINE_CONSTS` 的文件表格和 current source/test 在某些 edge values 的實際替換不同；例如 current test 明確驗證 integer `-1 → 0`，source 對 `Byte.MAX_VALUE`／`Short.MAX_VALUE` 有 overflow replacement。故若要回答「這個 PIT source 版本真的會改什麼」，應以 source implementation 和 test 為準，不把文件中的歷史表格當成 bytecode 的普遍定律。[官方文件](https://pitest.org/quickstart/mutators/)、[service registration](https://github.com/hcoles/pitest/blob/fcb9adc815ff7dbacbe91c65972a05f9a1ffb960/pitest/src/main/resources/META-INF/services/org.pitest.mutationtest.engine.gregor.MethodMutatorFactory)、[`Mutator.newDefaults`](https://github.com/hcoles/pitest/blob/fcb9adc815ff7dbacbe91c65972a05f9a1ffb960/pitest/src/main/java/org/pitest/mutationtest/engine/gregor/config/Mutator.java)、[`InlineConstantMutatorTest`](https://github.com/hcoles/pitest/blob/fcb9adc815ff7dbacbe91c65972a05f9a1ffb960/pitest/src/test/java/org/pitest/mutationtest/engine/gregor/mutators/InlineConstantMutatorTest.java)。
