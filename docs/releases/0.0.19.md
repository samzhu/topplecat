# ToppleCat 0.0.19

ToppleCat 0.0.19 gives Java teams one current-run answer to an implementation
agent's done claim: read the selected executable contract before handoff, then
see the result for each selected Acceptance Condition after Verify. It collects
the changes since the last published GitHub Release, 0.0.10, so teams can
upgrade directly without reconstructing intermediate tags.

## Review the selected contract, then the evidence for each AC

`toppleCatReview` writes the reviewer-only **Spec Review** before handoff, and
`toppleCatVerify` writes the reviewer-only **Verification Report** after the
formal run. The retired `build/topplecat/reports/public/` bundle is not
produced. Implementation Agents continue to receive only the public Java/JUnit
contract and safe `agent-feedback.json`.

Verification Report groups public Acceptance, Hidden Tests, Expected Result
Check, Property-Based Testing, and Mutation Testing under each selected AC.
Contract Integrity is reported once as the prerequisite for downstream work.
Both reviewer reports support `--language zh-TW`; only ToppleCat-owned
presentation is translated.

## See the temporary production changes an AC did not detect

Mutation Testing follows the selected Delivery Scope. Each unchanged public
Acceptance Method must detect every mutation exactly attributed to its AC; an
AC cannot receive credit because another Acceptance Method detected the same
change.

For an AC with undetected changes, the report shows the detected and undetected
counts and expands only the undetected changes. Each reviewer-only card states
what PIT changed, the available production source location, and that the AC's
public acceptance still passed. An exact before-and-after replacement appears
only when PIT's description and an unambiguous original source line establish
it. Otherwise the report preserves PIT's description and clearly says that an
exact source-level replacement is unavailable. The report now keeps that
fallback as valid HTML as well as valid evidence.

PIT outcomes, selectors, source coordinates, and other technical diagnostics
remain available to the Reviewer but never enter safe agent feedback.

## Keep generated Property input evidence reviewable

Property-Based Testing retains every discarded generator input as current-run
JSON evidence and paginates it in Verification Report. Public Acceptance
Methods and Properties use business-readable JUnit `@DisplayName` values, and
public Stage Steps use `@As` sentences, so the contract explains the business
situation rather than an implementation detail.

## Upgrade from 0.0.10

1. Update the Gradle plugin and `topplecat-junit` dependency to `0.0.19`.
2. Stop publishing or parsing `reports/public`; use reviewer-only Spec Review
   and Verification Report instead. Report readers must use
   `topplecat.review-view.v7` and `topplecat.verification-view.v9`.
3. Remove `mutationTesting { threshold.set(...) }`. Each attributed mutation
   must be detected by its own public Acceptance Method; no percentage setting
   replaces that rule.
4. When using `--spec`, select every public Acceptance Method in a test class,
   or move selected methods into a dedicated class before formal Verify.
5. Give public Acceptance Methods and Properties meaningful JUnit
   `@DisplayName` values, and give public Stage Steps `@As` sentences. Restore
   reviewer custody, then run Check, Review, and Reseal before formal Verify.

## Requirements and compatibility

Java 25 and the existing compatible Gradle and JUnit requirements are
unchanged. Formal Verify continues to manage PIT 1.25.5 internally and the
reviewer bundles remain offline. ToppleCat does not provide a compatibility
reader or dual writer for earlier report projections.
