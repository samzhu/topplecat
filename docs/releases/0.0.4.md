# ToppleCat 0.0.4

> Release: 0.0.4 · 2026-07-27

ToppleCat 0.0.4 fixes a misleading mutation result: PIT could finish without
running the public acceptance test that defines an AC. The build looked
successful, but the mutation score had not checked the contract you cared
about.

## Mutation must exercise the acceptance contract

ToppleCat now checks that PIT actually ran every required public canonical
`@ToppleTest`. This also works when production code and acceptance tests use
different Java packages.

The mutation result is now:

- `PASS` when the required acceptance tests ran and killed the required mutants;
- `FAIL` when PIT produced a usable report but skipped a required canonical
  test; or
- `INCOMPLETE` when PIT produced no usable current-run report.

Old mutation artifacts cannot fill a missing result. Safe agent feedback says
that public acceptance coverage is missing without revealing reviewer test
names, paths, or failures.

ToppleCat finds the canonical tests from compiler-generated contract
descriptors. This is an implementation detail; most projects do not need new
configuration.

## Reviewer rows no longer need a placeholder Java test

A reviewer can keep independent JSON or YAML cases under `src/hiddenTest` and
run them through the public canonical `@ToppleTest`. A Java helper without an
executable JUnit method no longer prevents this rows-only retest.

If reviewer rows and hidden Java tests both exist, both must pass. If neither
exists while hidden retest is enabled, `REVIEWER_JUNIT` remains `INCOMPLETE`
instead of becoming an empty pass.

## Do I need to change anything?

Most projects do not.

If your build sets PIT `targetTests`, ToppleCat keeps that setting. Make sure it
includes every public canonical acceptance test. A usable report that skips one
now fails the mutation gate.

Custom mutation producers still control their own targeting and report output.
They must produce a usable current-run report or the gate is `INCOMPLETE`. The
first mutation run after upgrading may take longer while ToppleCat builds the
contract descriptors and PIT matrix.

## What the mutation score covers

The default mutation score measures the strength of the public executable
contract. Reviewer rows and hidden Java tests are separate hidden-retest
evidence; they do not raise the public PIT score.
