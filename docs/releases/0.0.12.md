# ToppleCat 0.0.12

0.0.12 gives Java teams two faithful reviewer reports: read the complete selected
Spec before handoff, then see the actual verification finding and its own
evidence without a misleading count, blended score, or page-wide overflow.

## Read the selected Spec and the verification result in their proper places

`toppleCatReview` produces **Spec Review** before implementation verification.
It reads the complete selected Markdown document before the AC-bound Java
acceptance material, Typed Case Rows, Properties, and reviewer information.
`toppleCatVerify` produces the reviewer-only **Verification Report** after the
formal run, leading with the delivery conclusion and concrete failures.

The retired `build/topplecat/reports/public/` bundle is not produced. The
implementation agent continues to receive the original public executable
contract and safe `agent-feedback.json`; neither reviewer report is a second
source of truth.

Reviewer tooling that reads report `data.json` must use
`topplecat.review-view.v7` and `topplecat.verification-view.v9`. There is no
compatibility reader or dual writer for the earlier report projections.

## See what Property-Based Testing actually completed

The Verification Report now counts completed Properties from the sealed
current-run terminal event for each stable Java Property identity. Repeated or
edited display names cannot turn five completed Properties into zero, and a
counterexample still counts as completed evidence rather than disappearing from
the report header.

This corrects report evidence only. It does not change the `PROPERTY` Gate,
aggregate verdict, selected scope, trial execution, or the meaning of a
counterexample.

## Read diagnostics without losing the source or the page

Long Scenario text now reflows rather than widening the entire report. Tables
and source blocks keep their own horizontal scroll area when necessary. The
report's compiler-described Step sentence remains separate from structured Step
data, so a runtime object's arbitrary `toString()` cannot rewrite the
executable narrative.

Java source highlighting tokenizes before it emits markup, preserving comments,
strings, and escapes as source text. Mutation Testing also distinguishes PIT's
global outcome from the per-Acceptance-Method detection rate that the Mutation
Gate evaluates. These are reviewer explanations; no Gate, threshold, managed
PIT profile, attribution calculation, or expected-value rule changed.

## Upgrade

1. Update the Gradle plugin and `topplecat-junit` dependency to `0.0.12`.
2. If reviewer tooling reads generated report data, use the current
   `topplecat.review-view.v7` and `topplecat.verification-view.v9` projections;
   stop using `reports/public`.
3. A Mechanical Seal is current-version-only. Restore reviewer custody, then
   Check, Review, and Reseal before formal Verify.

The public Java/JUnit authoring API, Gradle task names, `--spec` selection,
six Gate names and order, evidence schemas, verification policy, and runtime
requirements are otherwise unchanged.

## Requirements

Java 25 and the existing compatible Gradle and JUnit requirements are
unchanged. Formal Verify continues to manage PIT 1.25.5 internally, and report
bundles remain offline.
