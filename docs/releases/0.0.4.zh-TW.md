# ToppleCat 0.0.4

> 發佈版本：0.0.4 · 2026-07-27

## 重點

- 預設 PIT producer 現在會以 compiler 產生的 contract descriptor，找出每一個
  public canonical `@ToppleTest` 宣告 class，並在 producer 執行前設定 PIT 的
  `targetTests`。因此 production package 與 public test package 不必同名，
  mutation verification 仍能對準真正的公開合約。

- Consumer 的 PIT 選擇仍具有最高優先權。Consumer 明確設定的 `targetTests`
  會原樣保留，custom mutation producer 也不會被覆寫。若可用的 PIT 報告沒有
  執行某個 canonical acceptance test，mutation gate 會記錄 `FAIL`；ToppleCat
  不會悄悄放寬 target，也不會把這種報告當成通過。

- PIT 輸出遺失、格式錯誤或執行中斷時，會記錄為 `MUTATION=INCOMPLETE`。當次
  gate 不完整時，aggregate verdict 不可能得到 `PASS`，也不會拿舊的 mutation
  artifact 充數。Safe agent feedback 只提供一般性的公開合約診斷，不會洩漏
  reviewer test 名稱、source path 或 PIT 原始錯誤。

- Reviewer-only JSON/YAML rows 可以重用 public canonical `@ToppleTest`；沒有
  hidden Java test 時，這支 canonical test 的結果會聚合成 reviewer retest。
  沒有可執行 JUnit method 的 helper Java source 只會被編譯，不會被算成 hidden test。
  若另外存在 hidden Java tests，它們仍須獨立通過；已啟用 retest 卻沒有 rows
  或 Java tests 時，會維持 `INCOMPLETE`。

## 升級提醒

使用受 ToppleCat 管理的 `pitest` producer 不需要新增 consumer 設定。升級後的
第一次執行可能較久，因為會產生 compiler descriptor 並執行完整 PIT mutation
matrix。如果 build 原本刻意設定 PIT `targetTests`，請保留該設定；ToppleCat
會尊重它，而 mutation 要通過仍必須由報告證明 public canonical contract 被執行。

Custom mutation producer 仍由使用者負責 test targeting 與報告完整性。若 custom
producer 沒有產生可用報告，現在會得到 `INCOMPLETE`，不能被解讀成 mutation
已通過。

## 界線

預設 mutation gate 衡量公開可執行合約的強度。Reviewer rows 與 reviewer-only
JUnit tests 仍是獨立的 hidden-retest 證據，不會提高預設 PIT score。Compiler
descriptor 只用來辨識 canonical classes 與 methods；產生的報表與 JSON 仍是
證據，不是另一套 authoring language 或真相來源。
