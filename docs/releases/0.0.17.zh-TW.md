# ToppleCat 0.0.17

ToppleCat 0.0.17 讓 Reviewer 能在交付前讀取同一份已選定的可執行契約，並在
Implementation Agent 宣稱完成後讀取驗證證據。這個版本收納了上一個已發布 GitHub
Release（0.0.10）以來的變更，團隊可以一次升級，不必自行重組中間的 tags。

## 先讀契約，再讀交付結果

`toppleCatReview` 會在 handoff 前產生 reviewer-only 的 **Spec Review**，呈現完整的
已選定 Spec 與其可執行 acceptance material。`toppleCatVerify` 會在正式執行後產生
reviewer-only 的 **Verification Report**，先說明具體結果和背後的證據。

已淘汰的 `build/topplecat/reports/public/` bundle 不再產生，也沒有替代用的 public
HTML。Implementation Agent 仍會取得原始的 public Java/JUnit contract 與安全的
`agent-feedback.json`。原本讀取已淘汰 `SpecView` projection 的整合必須移除。讀取
report `data.json` 的 reviewer tooling 必須改用 `topplecat.review-view.v7` 與
`topplecat.verification-view.v9`；ToppleCat 不提供舊 projection 的相容 reader 或 dual
writer。

兩份 reviewer report 都可使用 `--language zh-TW` 選擇英文或繁體中文。語言選擇只會
翻譯 ToppleCat 自己的呈現內容，不會改變 executable contract、evidence、policy 或
Gate verdict。

## 逐一理解每個 Acceptance Condition 的 Mutation Testing

Verification Report 現在會從每個 Acceptance Condition 的 plain-language 結果開始：
它的 acceptance test 跑過多少 mutation、抓到多少，以及是否符合 sealed requirement。
例如：「這個 test 跑過 10 個 mutation，抓到 8 個。你的 requirement 是 80%，所以符合
要求。」低於門檻或沒有可用資料時，也會直接說明原因。

原始 PIT status、mutator identifier、description、selector relationship 與 technical
Gate detail 仍可在摺疊的技術區段查看。executable contract、`MUTATION` Gate calculation、
mutation attribution、evidence schema 與 managed producer policy 都沒有改變。

## 精確計算已完成的 Property-Based Testing 證據

只有 Current-run Evidence 對 sealed contract identity 具有剛好一個相符的 `STARTED`
event，並接著一個相符 terminal event 時，Verification Report 才會把已選定的 Property
計為完成。重複、其他 run、過期或不完整的 lifecycle evidence 都不能把數量墊高。完成
與 Property-Based Testing outcome 仍是兩件事：有效的 pass、counterexample 或 incomplete
terminal event 都算完成證據，Gate 則保留自己的結果。

## 從 0.0.10 升級

1. 將 Gradle plugin 與 `topplecat-junit` dependency 更新為 `0.0.17`。
2. 停止發佈或解析 `reports/public`；移除 `SpecView` integration，並把 reviewer report
   reader 更新為 `topplecat.review-view.v7` 與 `topplecat.verification-view.v9`。
3. 原有命令可維持不變；Reviewer 想以繁體中文閱讀報告時，加上 `--language zh-TW`。
4. Restore reviewer custody，接著執行 Check、Review 與 Reseal，再做正式 Verify。
   Mechanical Seal 與 custody state 只支援目前版本。

## 環境需求與相容性

Java 25 與既有相容的 Gradle、JUnit 需求不變。正式 Verify 仍在內部管理 PIT 1.25.5，
report bundle 保持離線，Javadocs 也不再參照外部 web font。本版本不引入 Java API、
Gradle task name、selected-Spec option、Gate order 或 evidence schema 變更。

localization 變更。
