# ToppleCat 0.0.12

0.0.12 為 Java 團隊提供兩份忠實的 reviewer 報告：交接前閱讀完整已選 Spec，正式
執行後看見真正的驗證發現與各自證據，不會因錯誤計數、混合分數或整頁水平溢位而失真。

## 在正確的位置閱讀已選 Spec 與驗證結果

`toppleCatReview` 在實作驗證前產生 **Spec Review**。它會先閱讀完整已選 Markdown
文件，再呈現 AC 綁定的 Java 驗收材料、Typed Case Rows、Properties 與 reviewer 資料。
`toppleCatVerify` 則在正式執行後產生僅供 reviewer 查看的 **Verification Report**，先
呈現交付結論與具體失敗。

已淘汰的 `build/topplecat/reports/public/` bundle 不再產生。實作 agent 繼續取得原始
公開可執行契約與安全的 `agent-feedback.json`；兩份 reviewer 報告都不是第二份事實來源。

若 reviewer 工具會讀取 report `data.json`，必須使用
`topplecat.review-view.v7` 與 `topplecat.verification-view.v9`。舊 projection 沒有
compatibility reader 或 dual writer。

## 看見 Property-Based Testing 實際完成的數量

Verification Report 現在以每個 stable Java Property identity 在本次執行留下、並受
封印約束的 terminal event 計算已完成的 Properties。重複或改寫顯示名稱不會再把五個
完成的 Properties 顯示成零；找到 counterexample 也仍是已完成的證據，不會從頁首消失。

這只修正報告證據，不改變 `PROPERTY` Gate、整體 verdict、已選 scope、trial 執行或
counterexample 的意義。

## 保留原始內容，也不讓頁面失去可讀性

長 Scenario 文字現在會重新換行，不會撐寬整份報告。表格與原始碼在需要時仍各自在
自己的區塊內水平捲動。報告中的 compiler-described Step sentence 與結構化 Step data
分開，因此 runtime object 任意的 `toString()` 不會改寫可執行敘事。

Java 原始碼高亮會先 tokenization 再輸出 markup，保留 comment、string 與 escape
作為原始內容。Mutation Testing 也會分開 PIT 的 global outcome 與 Mutation Gate
實際判定的 per-Acceptance-Method detection rate。這些都是 reviewer 說明；沒有改變
任何 Gate、threshold、managed PIT profile、attribution calculation 或 expected-value
規則。

## 升級步驟

1. 將 Gradle plugin 與 `topplecat-junit` dependency 更新為 `0.0.12`。
2. 若 reviewer tooling 會讀取產生的 report data，請使用目前的
   `topplecat.review-view.v7` 與 `topplecat.verification-view.v9` projection，並停止使用
   `reports/public`。
3. Mechanical Seal 只適用目前版本。正式 Verify 前，請 Restore reviewer custody，接著
   Check、Review、Reseal。

公開 Java/JUnit authoring API、Gradle task 名稱、`--spec` 選取方式、六個 Gate 名稱與
順序、evidence schema、verification policy 與執行環境需求都沒有改變。

## 環境需求

Java 25 與既有相容的 Gradle、JUnit 需求沒有改變。正式 Verify 仍在內部管理 PIT 1.25.5，
報告 bundle 仍可離線使用。
