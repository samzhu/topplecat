# ToppleCat 0.0.3

## 已核准合約完整性

0.0.3 修補一個驗證完整性缺口：受委派的實作者先前可能連同 production code
一起改動可見的可執行合約，讓 public tests、hidden retests、expected-value
checks 與 mutation testing 都對著被改寫的合約呈現綠燈。

現在 Hide 會建立 version-2 escrow epoch，封存 reviewer 對下列內容的核准：

- 公開 test source 與 typed case data 的精確位元組；
- 相關的專案內 Gradle build logic；
- 公開語意 `ContractDefinition` digest；以及
- 已解析的 hidden-retest、expected-consumption 與 mutation policy。

`toppleCatVerify` 會新增必要的第一個 evidence gate：

```text
CONTRACT_INTEGRITY
JUNIT
REVIEWER_JUNIT
EXPECTED_CONSUMPTION
MUTATION
```

比較會在每次 run 重新執行並只對該 run 有效。若不相符，會記錄
`CONTRACT_INTEGRITY: FAIL`，不會把下游驗證當成最終證明，並將其餘四個 gate
記為 `INCOMPLETE`；接著仍會寫出安全 feedback 與 evidence、移除過期的公開
Spec bundle、重新隱藏 reviewer source，最後以 nonzero exit 結束。核准缺失或
legacy escrow 則是 `INCOMPLETE`，絕不會得到未封存的 PASS。

## 刻意演進與遷移

一般 Hide、Restore、Rehide 與 Verify 都會保留既有核准。若要核准公開合約、
policy 或 reviewer suite 的變更，授權 reviewer 必須依序執行：

```text
toppleCatRestore
    -> edit
    -> toppleCatCheck
    -> toppleCatReview
    -> reviewer accepts the review
    -> toppleCatUpdateEscrow
```

`toppleCatUpdateEscrow` 會原子啟用新版 hidden inventory 與 approval。既有
v1 escrow 仍可用於 Restore 與 Rehide，但首次 Verify 會是 `INCOMPLETE`，直到
依上述明確流程重新封存並遷移為 v2。

`evidence.json` 與 `agent-feedback.json` 維持 schema version 1；可擴充的
gate 清單新增 `CONTRACT_INTEGRITY`。安全 feedback 不會洩露 approval digest、
路徑、policy value、AC、case data 或 reviewer 細節。
