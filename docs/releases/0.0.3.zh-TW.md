# ToppleCat 0.0.3

ToppleCat 0.0.3 補上一個委派驗證的漏洞：審閱者核准之後，代理可能偷偷修改
公開測試、案例資料或驗證設定，再讓不完整的實作通過被改弱的合約。

## 合約被改過，不能沿用舊的核准

ToppleCat 現在會記錄審閱者核准時的公開可執行合約與驗證政策。之後只要內容
有變，`toppleCatVerify` 就會先回報 `CONTRACT_INTEGRITY: FAIL`，不會繼續
用其他關卡製造看似正常的結果。

這一關會抓出：

- 把較難達成的預期結果改成簡單答案；
- 刪除或更換驗收條件；
- 降低突變測試要求，讓不完整的實作過關。

如果是審閱者接受的正常變更，請依序執行 `toppleCatRestore`、
`toppleCatCheck`、`toppleCatReview` 和 `toppleCatUpdateEscrow`。一般的
`toppleCatHide` 或 `toppleCatVerify` 不會自行更新核准內容。

## 審閱資料移出專案目錄

審閱者原始碼與核准資料現在放在專案目錄外的
`~/.topplecat/projects/<project-key>/escrow/`。移動或重新複製專案時，
不會把審閱資料一起帶到另一份工作副本；只有公開檔案也無法建立新的核准。

## 升級提醒

舊版若在專案內留下 `.topplecat/escrow/`，請執行：

```bash
./gradlew toppleCatMigrateEscrow
```

搬移前，ToppleCat 會先檢查審閱檔案。舊保管區若已損壞會保留原狀；
兩個遷移工作同時執行，也不會刪掉已啟用的審閱資料。

版本 1 的保管資料還需要由授權審閱者依序執行 `toppleCatRestore`、
`toppleCatCheck`、`toppleCatReview`，再執行 `toppleCatUpdateEscrow`，
才能得到 `PASS`。流程請看
[驗證與證據指南](../guide/verification-and-evidence.md)。

如果 CI 會解析 ToppleCat JSON 報告，請把新增的 `CONTRACT_INTEGRITY`
檢查納入。其他使用者不必改設定。

發版驗證的正常輸出也變得安靜一些。已知的錯誤實作被成功攔下時，會顯示
攻擊檢查通過；非預期錯誤仍會保留完整診斷。

## 這一版不負責什麼

審閱資料保管區只是本機儲存，不是沙箱（sandbox）。`toppleCatVerify` 應在
可信任的審閱者或 CI 環境執行；交給實作代理的內容，只能包含公開工作副本
與安全回饋。
