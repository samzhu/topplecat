# ToppleCat 0.0.3

## 重點

- ToppleCat 現在會記住 reviewer 核准的公開合約。公開測試、case data、相關 Gradle
  logic 或驗證設定後來被改過，`toppleCatVerify` 就會以
  `CONTRACT_INTEGRITY: FAIL` 失敗。agent 不能把測試改弱來配合自己的實作，然後還得到 PASS。

- reviewer source 和核准資料現在放在 repository 外的
  `~/.topplecat/projects/<project-key>/escrow/`。專案被複製或重新 clone 時，不會誤用舊的
  reviewer state，也不能從 public files 自動建立新的核准。

- 舊版專案內的 escrow 可用 `./gradlew toppleCatMigrateEscrow` 明確搬移。ToppleCat 會先檢查
  reviewer 檔案；資料壞掉會保留原狀，兩個 migration 同時執行也不會刪掉已啟用的 state。

- 發版檢查現在會清楚說明：刻意放錯的實作已被成功擋下。正常輸出不再被雜訊淹沒；
  非預期錯誤仍會保留完整診斷。

## 升級提醒

如果你從舊版留下 `.topplecat/escrow/`，請執行：

```bash
./gradlew toppleCatMigrateEscrow
```

舊版 v1 escrow 還需要由授權 reviewer 依序 Restore、Check、Review，再執行
`toppleCatUpdateEscrow`，才能得到 PASS。完整流程請看
[驗證與證據指南](../guide/verification-and-evidence.md)。

只有你們的 CI 會自己讀 ToppleCat JSON 報告時才需要注意：報告現在多了一個
`CONTRACT_INTEGRITY` 檢查。一般使用者不需要做任何事。

## 界線

reviewer-local escrow 是本機儲存，不是 sandbox。Verify 應在可信任的 reviewer 或 CI
環境執行，交給 implementation agent 的只能是 public checkout 和 safe feedback。
