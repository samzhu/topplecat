# ToppleCat 0.0.8

0.0.8 makes every enabled Independent Safeguard leave an honest result from
the same formal run. It is compatible with the 0.0.7 public authoring surface:
there is no new annotation, DSL, command-line option, or `verifyAll` API.

## See every enabled safeguard's result

After `CONTRACT_INTEGRITY=PASS`, `toppleCatVerify` runs public acceptance,
Hidden Tests, Property-Based Testing, and Mutation Testing in that fixed order.
A completed gate that finds a problem records `FAIL` and does not stop later
enabled gates. Expected Consumption, evidence, reviewer/public reports, safe
feedback, and reviewer-source rehide complete before Gradle returns the one
aggregate `FAIL` or `INCOMPLETE`.

`INCOMPLETE` remains distinct from `FAIL`: it means a producer was interrupted
or current-run evidence is missing or malformed. Verify clears the configured
mutation report before its producer runs, so a previous report cannot become
current evidence—even when Gradle skips a consumer-owned producer. Verify also
rebuilds the checked definition before Integrity compares the existing seal and
discards an unarchived run workspace before starting. Property feedback distinguishes a counterexample from a task
or evidence interruption; Mutation feedback distinguishes surviving mutants
from missing or damaged producer evidence.

## Reuse the existing Mechanical Seal

Verify now checks the existing Mechanical Seal and reviewer custody internally.
It records that it reused the seal and did not update approval. If the seal is
absent, Verify safely reports `CONTRACT_INTEGRITY=INCOMPLETE` and directs the
reviewer to run `toppleCatSeal`; only `toppleCatSeal` and `toppleCatReseal`
create or replace approval.

## Write expected-value checks that can all run

Prefer one `c.verify("receipt", receipt)` for a full receipt projection. When
separate expected keys are necessary, put their `verify` calls in JUnit
`assertAll`. A failed `verify` is still `ASSERTED`; a later value not reached
because that assertion threw stays `UNTOUCHED`. A JUnit failure and an Expected
Consumption failure can therefore both be useful evidence, not duplicate
reporting.

## Upgrade

Update the plugin and JUnit dependency to `0.0.8`. Existing seals use the
current-only 0.0.8 policy/version format; after changing ToppleCat coordinates,
restore reviewer custody, Check, Review, and Reseal before Verify.

## Requirements

Java 25 and the existing compatible Gradle requirement are unchanged.
