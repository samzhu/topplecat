# ToppleCat 0.2.2

ToppleCat 0.2.2 讓 Java/JUnit 團隊可以在業務 Spec 的一個明確 marker 位置放入已檢查的
驗收投影，因此調整 Markdown 標題或新增一般 AC 引用時，不會再悄悄改變 selected scope。

## 在正確位置放入可執行驗收內容

每個 selected AC 現在使用一個精確、獨立一行的 marker，例如
`<!-- topplecat:acceptance:AC-CHECKOUT-001 -->`，同時作為 machine identity 與 Spec Review
插入點。Review 會依 marker order 在該處插入一份完整、已檢查的 projection，包含所有綁定的
scenario、typed row，以及有序的 Given/When/Then/And/But Step。不同 marker 可以連續出現，
也可以放在支援的文件層級任意位置。

## 在 Review 前拒絕含糊的 selected-Spec input

標題、一般 AC 引用與 marker 鄰近性都是作者文字，不是 declaration。Check 會拒絕 supplied
selected Markdown documents 中重複的 ID，並列出所有衝突位置；也會為 generic legacy marker、
格式錯誤 directive、container 或 inline lookalike 提供可修復診斷，絕不 fallback 到 heading-based
pairing。unselected files 與 `.feature` files 仍不在 selected scope 內。

## 升級

這是從 0.2.1 起的 breaking selected-Spec authoring change。請把每個 generic
`<!-- topplecat:acceptance -->` marker 換成精確的帶 ID marker，並將相同的
repository-relative `--spec` paths 傳給 Check、Review 與 scoped Verify。whole-contract Check、
Seal 與 Verify 不需要改動。
`toppleCatSeal` 仍封存完整可執行契約，而不是 selected Spec scope。

## 要求

ToppleCat 仍在 JDK 21 或 25 執行；使用端 source 可以 target Java 17、21 或 25，但 Gradle
執行環境必須是支援的 JDK。Maven Central 發布仍是維護者另外執行的工作。
