# ToppleCat 0.0.28

ToppleCat 0.0.28 讓 Java 團隊一開始就理解：agent 宣稱「完成」後，為什麼還需要再檢查一次；同時延續目前以新鮮證據檢驗交付的審閱流程。

## 先理解防線，再學技術細節

公開專案頁現在先講清楚 ToppleCat 的核心比喻：看見標著 `PASS` 的東西，頑皮貓會伸爪子試試它是否站得住。這個故事把看似完成的 agent 交付，連到從不同角度挑戰它的獨立檢查。專案頁仍是面向人類的說明頁，不會公開實際交付的證據，也不取代審閱者報告。

## 不削弱完整契約，快速驗證剛完成的功能

目前流程仍允許 Reviewer 用 `--spec` 路徑或重複指定 `--ac` ID（兩者不能混用），快速取得剛完成功能的正式證據。範圍執行只涵蓋選定的 Acceptance Conditions，報告也會說明範圍 `PASS` 不是完整專案的判定。`toppleCatSeal` 與完整可執行契約仍然維持專案範圍。

## 從 0.0.10 升級

將 Gradle plugin 與 `topplecat-junit` dependency 更新為 `0.0.28`。若從上一個已發布的 GitHub Release `0.0.10` 直接升級，也要停止使用已退役的 `build/topplecat/reports/public/` bundle，改用目前的 reviewer report projection，移除自訂 mutation threshold，並在正式 Verify 前 restore、Check、Review，再重新封存完整可執行契約。公開頁面的示範都是合成案例，不是 Implementation Agent handoff，也不是核准。

## 環境需求

Java 25 與相容的 Gradle 版本需求維持不變。本版沒有 Java/JUnit authoring API 或驗證契約格式變更。
