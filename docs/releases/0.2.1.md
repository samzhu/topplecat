# ToppleCat 0.2.1

ToppleCat 0.2.1 lets Java/JUnit teams review the complete canonical Markdown
they selected together with the exact executable acceptance projection, so an
implementation handoff no longer depends on a drifting second locator file.

## Review the selected business context beside its executable contract

Spec Review now renders every selected Markdown document once and inserts each
Acceptance Condition's checked Java/JUnit projection at its authored standalone
marker. A human or upstream workflow supplies one or more exact
repository-relative `.md` paths; the same repeated `--spec` path set flows
through Check, Review, and scoped Verify. CommonMark headings, markers,
ordinary references, authored formatting, source snapshots, nested case values,
accessible disclosures, and public/reviewer custody remain visible without
changing the executable contract.

## Remove selection drift and unsafe fallback

The former `topplecat-specs.json` locator, stable Spec key, AC inventory mirror,
and Python maintenance helper are removed. `.feature` files are not read,
registered, or translated. A selected failure stops instead of silently falling
back to whole-contract material; no-selection Check, Seal, and Verify still
support whole-contract maintenance, while Review requires `--spec` and never
claims whole-contract Review readiness. After Review, `toppleCatSeal` still
seals the complete executable contract; the release does not change Gate,
Evidence, or custody meaning.

## Reject mismatched or unsafe checked inputs

The product CommonMark parser is the authority for heading/marker structure and
aggregated source diagnostics. Selected paths reject absolute, traversal, and
symbolic-link inputs. Check and Review share immutable checked document, Java
source, and local asset bytes; stale selected handoffs are removed after a
failed selection, and Review refuses an asset or source changed after Check.

## Read large reports on the web or offline

Review navigation resolves ordinary AC references to one unique projection,
authored links and inline code remain intact, and the report keeps keyboard,
screen-reader, English, Traditional Chinese, narrow viewport, raw-HTML safety,
and large-report behavior. The public site and learning samples document the
same selected-Spec workflow.

## Requirements and upgrade action

ToppleCat runs on JDK 21 or 25; consumer source may target Java 17, 21, or 25
when Gradle runs on a supported execution JDK. This release line is not yet in
Maven Central, so use `./gradlew publishToMavenLocal` and put `mavenLocal()`
before `mavenCentral()` until a maintainer publishes it. Existing users must
replace the former locator workflow with repeated repository-relative `--spec`
paths and make Review selections explicit.
