# ToppleCat 0.0.2

Released on 2026-07-25.

ToppleCat 0.0.2 fixes four correctness problems in the verification gate:
expected values that were read but never checked, JSON number scale, updates to
an existing reviewer escrow, and a successful shell exit after a failed gate.

## Expected values must be checked

Every top-level `expected` key is an assertion obligation. Only
`ToppleCase.verify(...)` satisfies it. Reading a value through
`ToppleCase.expected(...)` records `READ`, not `ASSERTED`; leaving it untouched
records `UNTOUCHED`. With expected-consumption enforcement enabled, either
state fails the case after its test invocation returns.

A test can no longer pass simply because it deserialized an expected value.
The value has to be compared with production behavior.

## Equivalent JSON numbers compare equal

`ToppleCase.verify(...)` now compares JSON numbers recursively by exact
mathematical value. Values such as `200`, `200.0`, and `200.00` therefore
compare equal, including inside nested objects and arrays.

This is exact comparison, not an epsilon or floating-point tolerance.
Different numeric values, different object/array structures, and a number
versus numeric-looking text still fail.

## Reviewer contracts can be updated

An authorized reviewer can now change an already hidden reviewer suite without
discarding the previous custody state. Use:

```text
toppleCatRestore
    -> edit src/hiddenTest
    -> toppleCatCheck
    -> toppleCatReview
    -> reviewer accepts the review
    -> toppleCatUpdateEscrow
```

The previous reviewer state remains active until the replacement passes
validation. A failed update does not discard it. The local audit records counts,
not reviewer content, and ordinary `toppleCatHide` still rejects unreviewed
changes.

## A failed verdict now fails the build

Previously, evidence could say `FAIL` or `INCOMPLETE` while Gradle still exited
successfully. Automation that checked only the shell result could accept a
failed verification.

`toppleCatReport` and `toppleCatVerify` now fail the Gradle build when the
aggregate verdict is `FAIL` or `INCOMPLETE`. Reports, evidence, safe feedback,
and source re-hiding still complete before Gradle returns the failure. Public
and reviewer tests also run fresh instead of reusing cached results as current
evidence.

## Mutation score stays tied to public tests

The default PIT producer uses public test classes and public case rows from
`sourceSets.test`. Reviewer-only rows and JUnit tests remain separate
hidden-retest evidence and cannot raise the public mutation score.

If a boundary is required to kill a mutant, add it to the public executable
contract. ToppleCat does not calculate per-case mutation scores or infer the
scope of a custom producer.

## Compatibility

The `0.0.2` libraries and Gradle plugin use the
`io.github.samzhu.topplecat` coordinates. This release uses Java 25 and the
repository's Gradle 9.1.0 wrapper. ToppleCat remains pre-1.0.

There is no public `evidence.json` or `agent-feedback.json` schema change in
this release.
