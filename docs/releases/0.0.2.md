# ToppleCat 0.0.2

Released on 2026-07-25.

ToppleCat 0.0.2 tightens the parts of the verification gate that decide
whether an AI agent's "done" claim is real. It does not add another authoring
language or broaden the product beyond Java/JUnit delegation verification.

## Status and Compatibility

The `0.0.2` libraries and Gradle plugin are published under
`io.github.samzhu.topplecat`; its historical coordinates are `0.0.2`.

This release is developed with Java 25 and verified with the repository's
Gradle 9.1.0 wrapper. ToppleCat remains pre-1.0. There is no public
`evidence.json` or `agent-feedback.json` schema change in this release.

## Expected-Value Correctness

Every top-level `expected` key is an assertion obligation. Only
`ToppleCase.verify(...)` satisfies it. Reading a value through
`ToppleCase.expected(...)` records `READ`, not `ASSERTED`; leaving it untouched
records `UNTOUCHED`. With expected-consumption enforcement enabled, either
state fails the case after its test invocation returns.

This prevents a test from looking complete merely because it deserialized an
expected value without comparing it to production behavior.

## JSON Numeric Correctness

`ToppleCase.verify(...)` now compares JSON numbers recursively by exact
mathematical value. Values such as `200`, `200.0`, and `200.00` therefore
compare equal, including inside nested objects and arrays.

This is exact comparison, not an epsilon or floating-point tolerance.
Different numeric values, different object/array structures, and a number
versus numeric-looking text still fail.

## Reviewer Escrow Update

An authorized reviewer can now evolve an already hidden reviewer suite through
this explicit custody flow:

```text
toppleCatRestore
    -> edit src/hiddenTest
    -> toppleCatCheck
    -> toppleCatReview
    -> reviewer accepts the review
    -> toppleCatUpdateEscrow
```

`toppleCatUpdateEscrow` validates and stages the complete revised source set,
writes reviewer-local audit metadata containing counts rather than reviewer
content, preserves the previous active custody state until activation, and
recovers safely if validation or activation fails. Activation requests atomic
filesystem moves where supported and retains the same validation and recovery
path when they are unavailable. Ordinary `toppleCatHide` continues to reject
unreviewed changes to restored source.

## Public-Contract Mutation Scope

The default PIT producer is explicitly restricted to `sourceSets.test`: public
test classes and public case rows. Reviewer rows and reviewer-only JUnit tests
remain an independent hidden-retest safeguard and cannot inflate the public
mutation score.

This makes the score's meaning explicit: a boundary required to kill a mutant
belongs in the public executable contract. ToppleCat still does not produce
per-case mutation scores or infer the scope of a custom producer.

## Trustworthy Terminal Signal

`toppleCatReport`, and therefore `toppleCatVerify`, now fails the Gradle build
when the aggregate verdict is `FAIL` or `INCOMPLETE`. Evidence, safe agent
feedback, HTML reports, stable copies, and the archived run are written before
the failure is signalled. `toppleCatRehide` still runs as a finalizer.

The public and reviewer verification test tasks execute freshly for every
verification run and are not reused from Gradle's up-to-date or build caches as
if they were current evidence. A green final task now means aggregate `PASS`.
Explicitly `DISABLED` safeguards retain their existing aggregate semantics.

## Scope

This release does not add a second DSL, a CLI, Spec Kit integration, richer
agent diagnostics, per-case mutation scoring, remote reviewer custody, or
artifact attestation. Those concerns remain outside the 0.0.2 correctness
release.
