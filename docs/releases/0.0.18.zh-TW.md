# ToppleCat 0.0.18

ToppleCat 0.0.18 讓 Java 團隊能讓 Implementation Agent 的完成宣稱先贏得本次執行的
`PASS`：Reviewer 先讀取已選定的可執行契約，接著清楚看見哪一個已選 Acceptance
Condition 有沒有偵測到暫時變更的正式行為。這個版本收納了上一個已發布 GitHub
Release（0.0.10）以來的工作，團隊可以一次升級，不必自行重組中間的 tags。

## 交付前讀取已選契約，交付後逐一閱讀 AC

`toppleCatReview` 會在 handoff 前產生 reviewer-only 的 **Spec Review**；
`toppleCatVerify` 則會在正式執行後產生 reviewer-only 的 **Verification Report**。
已淘汰的 `build/topplecat/reports/public/` bundle 不再產生；Implementation Agent
仍會取得公開 Java/JUnit contract 與安全的 `agent-feedback.json`。讀取 report
`data.json` 的 reviewer tooling 必須使用 `topplecat.review-view.v7` 與
`topplecat.verification-view.v9`。

Verification Report 現在只在主摘要呈現一次 Contract Integrity。Mechanical Seal
符合時，摘要會說明下游 AC 工作已執行；不符合或缺少可信完整性證據時，則明確說明
未執行，而不會把未執行的 AC 說成產品功能失敗。兩份 reviewer report 都支援
`--language zh-TW`；語言選擇只翻譯 ToppleCat 自己的呈現內容。

## 讓每個已選 AC 偵測歸因給自己的 mutation

Mutation Testing 現在跟隨已選交付範圍。每一個已選 AC 的未改動公開 Acceptance
Method，都必須偵測到每一個精確歸因給它的 mutation。即使另一個 AC 殺掉同一個
mutation，原本覆蓋它卻仍通過的 AC 還是可能漏掉它。報表會先顯示每個 AC 已評估、
已偵測與未偵測的數量，再呈現 reviewer-only 卡片，說明未偵測的正式行為改變、
可用的原始碼位置與證據限制。

不再有百分比或全專案 mutation 分數。這讓失敗的意思更精確：擁有該 mutation 的
Acceptance Method 跑過改變後的行為卻仍然通過。PIT 原始結果、selector、原始碼座標
與技術細節仍是 reviewer-only，不會進入安全的 agent feedback。

為了確保已選 AC 範圍精確，若選定的 Acceptance Method 和未選定的公開 Acceptance
Method 同屬一個 test class，正式 Verify 會在 PIT 前停止。PIT 無法用分開這些方法
所需的 compiler JVM descriptor 選取測試。

## 讓產生出的 Property 輸入可供審閱

Property-Based Testing 現在會把每一個被捨棄的 generator input 保留成 JSON evidence，
並在 Verification Report 分頁呈現。公開 Acceptance Method 與 Property 都使用
具商務意義的 JUnit `@DisplayName`；公開 Stage Step 則使用 `@As` 句子，因此給人讀的
contract 會描述正在驗證的商務情境，而不是實作細節。

## 從更清楚的公開專案頁開始

改版後的公開專案頁，以 reports 相同的本次執行 `PASS` 承諾開場，說明為何獨立的
safeguard 不能互相取代，並清楚保留 Reviewer 的交付決定權。英文與繁體中文頁面
維持相同邊界；公開頁面也為可見內容提供分享與搜尋中繼資料。

## 從 0.0.10 升級

1. 將 Gradle plugin 與 `topplecat-junit` dependency 更新為 `0.0.18`。
2. 停止發佈或解析 `reports/public`；移除 `SpecView` integration，並把 reviewer
   report reader 更新為 `topplecat.review-view.v7` 與
   `topplecat.verification-view.v9`。
3. 移除 `mutationTesting { threshold.set(...) }`。現在每個已歸因 mutation 都必須由
   自己的公開 Acceptance Method 偵測；百分比設定不能取代這條規則。
4. 使用 `--spec` 時，請選取一個 test class 中全部的公開 Acceptance Method，或在
   正式 Verify 前把已選方法移到專屬 class。
5. 為公開 Acceptance Method 與 Property 加上有意義的 JUnit `@DisplayName`，並為
   公開 Stage Step 加上 `@As` 句子。Restore reviewer custody 後，依序執行 Check、
   Review 與 Reseal，再做正式 Verify。

## 環境需求與相容性

Java 25 與既有相容的 Gradle、JUnit 需求不變。正式 Verify 仍在內部管理 PIT
1.25.5，reviewer bundles 維持離線。以上命名的 report schema 是目前支援的 reader
contract；ToppleCat 不提供舊 projection 的相容 reader 或 dual writer。
