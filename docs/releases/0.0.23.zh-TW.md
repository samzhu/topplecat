# ToppleCat 0.0.23

ToppleCat 0.0.23 讓審閱者先掃讀長篇 Verification Report 的結果，再只展開需要的 AC 細節，而且不會失去閱讀位置。

## 先看重點結果，再打開長報告

每個 Acceptance Condition 現在都從關鍵結果層開始：AC ID、標題、狀態、白話結果與五項防護結果會保持可見。可用 **展開這個 AC** 閱讀一個 AC 的所有案例，或用 **展開所有 AC** 以可取消的瀏覽器批次逐步展開。**這個 AC：只看重點結果** 與 **所有 AC：只看重點結果** 可回到精簡檢視。

例如，審閱者可先找出失敗的優惠券 AC，展開案例與預期值／實際值差異，接著把完整報告收回關鍵結果。技術證據仍是獨立收合的選擇，打開閱讀細節不會連帶暴露無關的 Gate 或 producer 診斷。

Needs Attention 連結、防護結果連結與 URL fragment 會先打開必要的閱讀路徑，再移動到目標。報告會在執行時量測 sticky 閱讀工具列與目前 AC 列，因此無論桌面或窄版畫面，連到完整預期值、Scenario 執行或原始失敗時，目標都會落在控制列下方。

## 讓被挑戰的防護結果取得焦點

相同固定順序的五個防護摘要，現在會讓發現問題或無法完成評估的防護取得視覺焦點，
並在旁顯示已記錄、可供讀者理解的原因。Gate 意義、證據值與逐層展開行為都沒有改變。

公開專案頁也加入六個可重現的合成結帳示範。每張卡片使用公開安全的
Verification Report 摘錄，並以原生 dialog 說明改變了什麼、ToppleCat 觀察到什麼、
Gate 判定、結果支持什麼，以及不能證明什麼。這些案例只用於說明，不是公開的
Verification Report，也不是組織核准。

## 先看哪裡有問題，再看執行細節

每個驗收條件現在會先顯示五項防護摘要，使用「通過」、「發現問題」、「已完成比對」與「無法評估」等閱讀結果。Canonical Gate 判定與 producer 術語仍保留在收合的技術證據中，不會被刪除或重新命名。

案例失敗時，報告會先顯示已撰寫的輸入，再用欄位表格並列預期值與實際值。完整預期資料、Scenario 執行步驟、傳入步驟的值與原始失敗資訊，仍可在下一層展開查看。報告也會明確提醒：若某項業務規則沒有出現在比對中，不能只因 AC 標題提到它，就當作已經檢查。

## 分清楚「有比對」與「有通過」

當所有已撰寫的預期值都與程式結果進行比較時，Expected Result Check 現在會顯示「已完成比對」。這只表示比對有執行，不代表兩邊相同；是否相同要看 Public Acceptance 與結構化差異表。

如果原始程式的 Public Acceptance 已經發現問題，Mutation Testing 會顯示「無法評估」，並說明本次執行缺少通過的比較基準。原始 PIT 診斷仍可供查閱，但不會被呈現為該 AC 的 Mutation Testing 判定。

## 在原地理解突變測試術語

Verification Report 現在會在 Mutation Testing 與初始突變卡片術語旁放置依報告語言在地化的 `ⓘ` 控制。滑鼠移入或鍵盤聚焦會顯示短說明；點擊或點按會固定說明，按 Escape 或點擊外部即可關閉。即使不打開說明，結果仍然可見；這項控制不會改變報告 JSON、evidence、Gate 或安全 agent feedback。

## 從 0.0.10 升級

上一個正式發布的 GitHub Release 是 0.0.10；0.0.11 到 0.0.20 只有 tags，沒有發布成 GitHub Releases。若直接從 0.0.10 升級，請完成下列調整：

1. 將 Gradle plugin 與 `topplecat-junit` dependency 更新為 `0.0.23`。
2. 停止發布或解析已淘汰的 `build/topplecat/reports/public/`，並移除對舊 `SpecView` 投影的整合。
3. 將審閱報告 reader 更新為 `topplecat.review-view.v7` 與 `topplecat.verification-view.v10`。舊投影沒有相容 reader 或雙格式 writer。
4. 移除 `mutationTesting { threshold.set(...) }`。每個公開 Acceptance Method 都必須偵測出精確歸因到自身 AC 的所有突變。
5. 使用 `--spec` 時，請選取同一測試類別中的所有公開 Acceptance Methods，或在正式 Verify 前把選取的方法移到專用類別。
6. 先恢復 reviewer custody，再執行 Check、Review 與 Reseal，最後才 Verify。Mechanical Seal 與 custody 格式只適用目前版本。

兩份審閱報告都支援僅限當次指令的 `--language zh-TW`。Property 完成數只計入一組符合本次執行的生命週期證據；被捨棄的產生輸入也會保留為審閱證據。這些能力來自中間 tags，並包含在本次直接升級路徑中。

## 環境需求

仍需要 Java 25 與相容的 Gradle 版本。正式 Verify 會繼續在內部管理 PIT 1.25.5，審閱報告也維持離線與 CSP-safe。0.0.23 沒有變更公開 Java/JUnit 撰寫 API 或 machine evidence schemas。
