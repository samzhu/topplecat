# ToppleCat 0.2.0

ToppleCat 0.2.0 讓 Java 團隊可以在 JDK 21 上執行驗證閘門，同時保留 Java
25 作為主要建置與發布環境。

## 不必使用 Java 25 runtime 也能採用 ToppleCat

0.1.0 的 artifact 需要 Java 25。從 0.2.0 開始，四個發布模組、Gradle
plugin、report、JUnit integration 與正式 Verify 流程都能在 JDK 21 或 JDK
25 上執行。單一 artifact family 以 Java 21 bytecode 為 target，並由 JDK
25 使用明確的 `--release 21` policy 建置。

## Java 17 source 專案仍可在支援的執行 JDK 上使用

使用端專案可以繼續 target Java 17 source，也可以 target Java 21 或 Java
25 source；前提是 Gradle/plugin 的執行環境使用 JDK 21 或 JDK 25。只使用
JDK 17 的環境無法載入或執行以 Java 21 為 target 的 ToppleCat artifact。Java
25 仍是支援的 runtime 與 consumer source line。

## 在 CI 與 artifact 中看見發布邊界

Release checks 包含 JDK 21 minimum line、JDK 25 primary release line、JDK
17 unsupported-runtime guard，以及明確的 consumer source/runtime fixtures。
Release gate 會掃描四個模組 JAR 的每一個 class 與 Gradle publication
metadata，在發布前拒絕較新版本或 preview bytecode。

## 使用雙語文件學習工作流程

公開 project site 現在提供雙語產品文件，以及獨立的 JUnit cart-orders
學習專案，展示五項 synthetic safeguard。這些示範只用來解釋產品，不是實際
交付的 evidence 或 approval。

## 升級

將 Gradle plugin 與 `topplecat-junit` dependency 從 `0.1.0` 更新為 `0.2.0`，
並使用 JDK 21 或 JDK 25 執行 build。如果專案保留 0.1.0 的 reviewer custody，
請先還原，執行 Check 與 Review，再依 0.2.0 policy 重新封存後執行正式 Verify；
reviewer custody 只支援目前版本。

當使用端的執行環境是 JDK 21 或 JDK 25 時，不需要為了 Java 17 source 改寫程式。

`toppleCatSeal` 仍會封存完整可執行契約。快速的有限範圍驗證可以使用 `--ac`，但 CI
仍應執行不指定範圍的完整命令。

## 環境需求

ToppleCat runtime 與 Gradle/plugin 執行需要 JDK 21 或 JDK 25。維護者建置與
Central publication preflight 使用 JDK 25。使用端 source 可以 target Java 17、
21 或 25，但 ToppleCat 必須在 JDK 21 或 JDK 25 上執行。
