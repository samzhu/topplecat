# ToppleCat 0.0.20

ToppleCat 0.0.20 makes a Verification Report easier to review one Acceptance
Condition at a time, so a reviewer can see the actual problem without decoding
tool terminology first.

## Read every AC in one fixed order

The AC-first Verification Report now keeps Public Acceptance, Hidden Tests,
Expected Result Check, Property-Based Testing, and Mutation Testing together
on every AC card. The problem summary links directly to the affected AC, while
the technical evidence remains available for audit without taking over the
main reading path.

Property-Based Testing now says how many generated inputs completed out of the
requested amount, how many were discarded, and when a counterexample stopped a
run early. This makes a result such as `12 of 200` meaningful to a reviewer.

## Keep Mutation Testing honest after a public failure

Mutation Testing now requires a passing Public Acceptance baseline. When a
public case already fails, its Mutation Testing result is `INCOMPLETE` rather
than a misleading claim about whether changed production behavior was detected.
Hidden Tests and Property-Based Testing still report their own independent
current-run evidence.

## Upgrade

Update the Gradle plugin and `topplecat-junit` dependency to `0.0.20`. No
source-code migration is required.

## Requirements

Java 25 and a compatible Gradle version remain required.
