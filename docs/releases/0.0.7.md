# ToppleCat 0.0.7

0.0.7 is the sole supported ToppleCat version. It is a breaking release with
one executable acceptance-authoring model and current-only reviewer custody.

## Use the single Scenario API

Each `@ToppleAcceptanceTest` receives `ToppleCase`, one `ToppleScenario`, and
concrete capability `ToppleStage` parameters. It selects direct Given, When,
Then, and And Steps; ordinary Java fields keep state within the Stage for a
Typed Case Row.

The earlier field annotations, state-transfer annotations, fluent helpers,
runtime recording helpers, sentence helper, and alternate acceptance aliases
are removed. There is no compatibility layer or alternate authoring form.

## Keep safeguards independent

Hidden Tests, Mutation Testing, and Property-Based Testing have separate
inputs, tasks, policies, evidence, and gates. Properties are public bounded
invariants; they neither use Hidden Tests nor contribute hidden coverage or
mutation scores. PIT remains the default Mutation Testing producer.

## Seal current reviewer material

Use `toppleCatSeal` before handoff and `toppleCatReseal` after an authorized
reviewer revision. Approval and custody read only the 0.0.7 schema; create a
new reviewer state for this version. Reviewer custody is plaintext mechanical
storage, while current-run evidence—not an archive—is the final verdict.

## Updated guidance

The root `CONTEXT.md` is the canonical glossary. Documentation, samples, the
site, and the `topplecat-acceptance` skill use the same terms and Scenario API.
The skill helps turn selected Acceptance Conditions into Java/JUnit methods,
public and reviewer Typed Case Rows, and optional Properties; people or an
external workflow still run ToppleCat and accept its result.
