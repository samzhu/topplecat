# ToppleCat 0.0.17

ToppleCat 0.0.17 gives a Reviewer one faithful path to read the selected
executable contract before handoff and the evidence after an implementation
agent claims done. It collects the changes tagged since the last published
GitHub Release, 0.0.10, so teams can upgrade once instead of reconstructing
intermediate tags.

## Read the contract first, then the delivery result

`toppleCatReview` writes the reviewer-only **Spec Review** before handoff. It
shows the complete selected Spec alongside its executable acceptance material.
`toppleCatVerify` writes the reviewer-only **Verification Report** after the
formal run and leads with the concrete result and the evidence behind it.

The retired `build/topplecat/reports/public/` bundle is no longer produced, and
there is no replacement public HTML. Implementation agents continue to receive
the original public Java/JUnit contract and safe `agent-feedback.json`.
Integrations that read the retired `SpecView` projection must be removed.
Reviewer tooling that reads report `data.json` must use
`topplecat.review-view.v7` and `topplecat.verification-view.v9`; ToppleCat does
not provide a compatibility reader or dual writer for earlier projections.

Both reviewer reports can be rendered in English or Traditional Chinese with
`--language zh-TW`. The language choice translates only ToppleCat-owned
presentation; it never changes the executable contract, evidence, policy, or
Gate verdict.

## Understand Mutation Testing one Acceptance Condition at a time

For each Acceptance Condition, the Verification Report now starts Mutation
Testing with a plain-language result: how many mutations its acceptance test
ran, how many it caught, and whether that meets the sealed requirement. For
example, “The test ran against 10 mutations and caught 8. Your requirement is
80%, so this meets the requirement.” A below-threshold or unavailable result
states the reason just as directly.

Raw PIT statuses, mutator identifiers, descriptions, selector relationships,
and the technical Gate details remain available in a collapsed technical
section. The executable contract, `MUTATION` Gate calculation, mutation
attribution, evidence schema, and managed producer policy are unchanged.

## Count completed Property-Based Testing evidence precisely

Verification Report counts a selected Property as completed only when
Current-run Evidence contains exactly one matching `STARTED` event followed by
one matching terminal event for the sealed contract identity. Duplicate,
foreign-run, stale, or incomplete lifecycle evidence cannot inflate the count.
Completion remains separate from the Property-Based Testing outcome: a valid
pass, counterexample, or incomplete terminal event counts as completed evidence
while the Gate reports its own result.

## Upgrade from 0.0.10

1. Update the Gradle plugin and `topplecat-junit` dependency to `0.0.17`.
2. Stop publishing or parsing `reports/public`; remove `SpecView` integrations
   and update reviewer report readers to `topplecat.review-view.v7` and
   `topplecat.verification-view.v9`.
3. Keep existing commands, or add `--language zh-TW` when the Reviewer wants
   Traditional-Chinese report presentation.
4. Restore reviewer custody, then run Check, Review, and Reseal before formal
   Verify. A Mechanical Seal and custody state are current-version-only.

## Requirements and compatibility

Java 25 and existing compatible Gradle and JUnit requirements are unchanged.
Formal Verify continues to manage PIT 1.25.5 internally, report bundles remain
offline, and Javadocs no longer reference an external web font. No Java API,
Gradle task name, selected-Spec option, Gate order, or evidence-schema change
is introduced by this release.
