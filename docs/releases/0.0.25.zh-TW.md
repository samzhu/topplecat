# ToppleCat 0.0.25

ToppleCat 0.0.25 讓 Reviewer 可以為剛完成的驗收條件快速取得正式證據，同時不會把這個結果
誤認成完整專案的驗證。

## 只驗證剛改完的 AC

不帶選項的 `toppleCatVerify` 仍會驗證完整可執行契約，這也是 CI 的正常指令。若要更快地
正式確認範圍，Reviewer 現在可指定 repository 內的 Spec 文件，或重複指定 `--ac AC-...`
ID；兩種不能混用：

```bash
./gradlew toppleCatVerify --spec specs/checkout/spec.md
./gradlew toppleCatVerify --ac AC-CHECKOUT-THRESHOLD --ac AC-CHECKOUT-VIP
```

選定範圍後，公開驗收、Hidden Tests、Property-Based Testing 與 Mutation Testing 的防線仍會
執行。Verification Report 會標出選取來源與 AC ID；範圍 `PASS` 現在會明說只涵蓋這些 AC，
不代表完整可執行契約通過。

## 保管與完整性一律以整個專案為單位

`toppleCatSeal` 與 `toppleCatReseal` 現在一律處理完整可執行契約與驗證政策，並拒絕
`--spec`、`--ac`。這避免把 reviewer custody 或 Mechanical Seal 誤解成只屬於某一個功能。
即使之後的 Verify 指定範圍，Contract Integrity 仍會比對完整契約。

## 從 0.0.24 升級

1. 將 Gradle plugin 與 `topplecat-junit` dependency 更新為 `0.0.25`。
2. 從 Seal 與 Reseal 指令移除 `--spec`、`--language`。若要閱讀繁中 Review，請使用
   `toppleCatReview --language zh-TW`。
3. CI 請使用不指定範圍的 `toppleCatVerify`。本機要確認功能時，請選擇 `--spec` 路徑或
   重複指定 `--ac` ID 其中一種。
4. 正式 Verify 前請建立目前版本的 Mechanical Seal。既有 custody 與 approval state
   只適用於目前版本；更新既有 reviewer suite 時，請 restore 後依序執行 Check、Review、
   Reseal。

## 環境需求

仍需要 Java 25 與相容的 Gradle。公開 Java/JUnit 撰寫 API 不變；本版調整 Gradle task
行為、審閱報告呈現與目前版本的 Mechanical Seal 格式。
