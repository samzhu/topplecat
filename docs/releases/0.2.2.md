# ToppleCat 0.2.2

ToppleCat 0.2.2 lets Java/JUnit teams place each checked acceptance projection
at one explicit business-Spec marker, so changing a Markdown heading or adding
an ordinary AC reference can no longer silently change selected scope.

## Place executable acceptance material exactly where it belongs

Each selected AC now uses one exact standalone marker, such as
`<!-- topplecat:acceptance:AC-CHECKOUT-001 -->`, as both its machine identity
and its Spec Review insertion point. Review inserts one complete checked
projection there, in marker order, including every bound scenario, typed row,
and ordered Given/When/Then/And/But Step. Different markers may be consecutive
or appear anywhere at the supported document level.

## Reject ambiguous selected-Spec input before Review

Headings, ordinary AC references, and marker proximity are authored prose, not
declarations. Check rejects duplicate IDs across the supplied selected Markdown
documents and reports every conflicting location. It also gives repairable
diagnostics for generic legacy markers, malformed directives, and container or
inline lookalikes; none falls back to heading-based pairing. Unselected files
and `.feature` files remain outside selected scope.

## Upgrade

This is a breaking selected-Spec authoring change from 0.2.1. Replace every
generic `<!-- topplecat:acceptance -->` marker with an exact ID-bearing marker,
and pass the same repository-relative `--spec` paths to Check, Review, and
scoped Verify. No change is required for whole-contract Check, Seal, or Verify.
`toppleCatSeal` continues to seal the complete executable contract, not a
selected Spec scope.

## Requirements

ToppleCat still runs on JDK 21 or 25; consumer source may target Java 17, 21,
or 25 when Gradle runs on a supported execution JDK. Maven Central publication
remains a separate maintainer action.
