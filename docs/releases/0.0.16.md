# ToppleCat 0.0.16

ToppleCat 0.0.16 lets a Reviewer read both private HTML reports in Traditional
Chinese without translating the executable contract, current-run evidence, or
an implementation agent's safe feedback mentally.

## Read Reviewer reports in your chosen language

Spec Review and Verification Report now accept an invocation-only
`--language en` or `--language zh-TW` option. English remains the default.

For example, a Reviewer can prepare a Chinese Spec Review with:

```bash
./gradlew toppleCatReview --spec specs/checkout/spec.md --language zh-TW
```

The same choice works with `toppleCatSeal`, `toppleCatReseal`, and
`toppleCatVerify`. Seal and Reseal pass it to their dependent Spec Review, so
the stable review report remains in the requested language.

Traditional Chinese localizes ToppleCat-owned headings, controls, accessibility
text, explanations, empty states, and fallbacks. The reports remain offline,
self-contained, escaped, and CSP-safe.

## Preserve the contract and evidence exactly

`@DisplayName`, `@As`, Property titles, selected Markdown, Typed Case Row
content, raw failures, AC IDs, Gate names and verdicts, and PIT producer
outcomes are not translated. Traditional Chinese authored text is preserved
through the compiler descriptors, runtime narrative, report JSON, and HTML.

Language selection is presentation only. It does not alter Delivery Scope, the
Executable Contract, Mechanical Seal, Gate verdicts, Current-run Evidence, or
`agent-feedback.json`.

## Upgrade

1. Update the Gradle plugin and `topplecat-junit` dependency to `0.0.16`.
2. Keep existing commands unchanged, or add `--language zh-TW` when the
   Reviewer wants Traditional Chinese report presentation.
3. Use only `en` or `zh-TW`; an unsupported or blank explicit value fails
   before formal Verify work begins.

## Requirements

Java 25 and the existing compatible Gradle and JUnit requirements are
unchanged. No translation service, font download, browser locale, environment
variable, or persistent Gradle setting is used.
