# ToppleCat 0.0.6

> Verify the Spec being delivered today without rerunning every older hidden
> retest, while keeping the full public and mutation safeguards in place.

## Why upgrade

- **Keep verification focused on the current delivery.** Pass one or more
  Markdown files with `--spec`. ToppleCat uses their `AC-...` IDs to run the
  matching reviewer-only checks. Public JUnit and mutation still cover the
  complete executable contract.
- **Catch a changed question before accepting the answer.** Hide seals the
  selected Spec paths, contents, and AC set. Verify fails contract integrity if
  the selection or document changes after handoff.
- **Require proof that reviewer checks actually ran.** Every selected AC needs
  current-run evidence from an executed hidden row or tagged reviewer Java
  test. A comment, string, plain `@Test`, or disabled test cannot make the
  reviewer gate pass.
- **See exactly what was verified.** Review and verification reports show the
  selected delivery scope and render each case as readable Given, When, and Then
  steps from the same Java contract that JUnit executes.

For example:

```bash
./gradlew toppleCatCheck --spec specs/023-checkout/spec.md
./gradlew toppleCatReview --spec specs/023-checkout/spec.md
./gradlew toppleCatHide --spec specs/023-checkout/spec.md

# The implementation agent works against the public contract.
./gradlew test

./gradlew toppleCatVerify --spec specs/023-checkout/spec.md
```

Repeat `--spec` when one delivery spans several documents. Add `--all-hidden`
to Verify only when the reviewer wants every AC-bound hidden check to run.

## Upgrade

Update both the plugin and `topplecat-junit` dependency to `0.0.6`.

```kotlin
plugins {
    id("io.github.samzhu.topplecat") version "0.0.6"
}

dependencies {
    testImplementation(
        "io.github.samzhu.topplecat:topplecat-junit:0.0.6"
    )
}
```

Projects without existing reviewer custody need no migration.

If reviewer custody was created by 0.0.5, an authorized reviewer must reseal it
once because 0.0.6 adds the delivery scope to the integrity snapshot. ToppleCat
validates and reads the old approval as the previous full-contract scope; it
does not silently approve the new policy.

```bash
./gradlew toppleCatRestore
./gradlew toppleCatCheck --spec specs/023-checkout/spec.md
./gradlew toppleCatReview --spec specs/023-checkout/spec.md
./gradlew toppleCatUpdateEscrow --spec specs/023-checkout/spec.md
```

Omit `--spec` in all three scoped commands if the project intends to keep
full-contract verification. Use the same Spec selection for the later Verify.

## Compatibility changes

There are no breaking changes to the Java authoring API or to commands that do
not use `--spec`.

Tools that parse reviewer-only report `data.json` files must accept
`topplecat.review-view.v3` and `topplecat.verification-view.v5`. The added
delivery-scope fields do not change the public `evidence.json` or
`agent-feedback.json` schema.
