# ToppleCat 0.0.13

ToppleCat 0.0.13 makes the Verification Report's Property completion count match what the current run can actually prove, so incomplete or mismatched lifecycle evidence no longer inflates the reported delivery scope.

## See only fully evidenced Property executions

Previously, a Property with only a terminal event, duplicate events, an event from another run, or mismatched contract identity could still increase the completed count. The Verification Report now counts a selected sealed Property only when Current-run Evidence contains exactly one `STARTED` event followed by exactly one matching terminal event for the run ID, Acceptance Condition ID, complete Java method identity, and source digest.

Completion is separate from outcome. A valid `COMPLETED_PASS`, `COMPLETED_COUNTEREXAMPLE`, or `COMPLETED_INCOMPLETE` lifecycle counts as completed; the `PROPERTY` Gate remains `PASS`, `FAIL`, or `INCOMPLETE` according to that outcome and the existing evidence checks.

## Upgrade

There are no breaking Java API, evidence schema, Gradle DSL, or configuration changes. Users do not need to modify their executable acceptance contract. Update the Gradle plugin and `topplecat-junit` dependency to `0.0.13` when upgrading.

## Requirements

JDK, Gradle, JUnit, and PIT requirements are unchanged. Formal Verify continues to manage the existing PIT version, and report bundles remain offline.
