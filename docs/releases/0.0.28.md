# ToppleCat 0.0.28

ToppleCat 0.0.28 gives Java teams a clearer first explanation of why an
agent's `done` claim needs a second look, while carrying the current reviewer
workflow for checking that delivery with fresh evidence.

## Understand the gate before learning the mechanics

The public project page now opens with ToppleCat's central metaphor: a
mischievous cat nudges anything labelled `PASS` to see whether it holds up.
The same story connects an agent's apparently finished delivery to the
independent checks that challenge it from different angles. The page remains a
human-facing explanation surface; it does not expose evidence from an actual
delivery or replace the reviewer reports.

## Verify a finished feature without weakening the project seal

The current workflow still lets a Reviewer obtain quick formal evidence for a
finished feature with either `--spec` paths or repeated `--ac` IDs, never both.
The selected run covers the chosen Acceptance Conditions and its report says
that a scoped `PASS` is not a complete-project verdict. `toppleCatSeal` and the
complete executable contract remain project-wide.

## Upgrade from 0.0.10

Update the Gradle plugin and `topplecat-junit` dependency to `0.0.28`.
Teams upgrading directly from the last published GitHub Release, `0.0.10`,
should also stop consuming the retired `build/topplecat/reports/public/`
bundle, use the current reviewer report projections, remove custom mutation
threshold configuration, and restore, Check, Review, and reseal the complete
executable contract before formal Verify. The public page's demonstrations
are synthetic and are not an Implementation Agent handoff or approval.

## Requirements

Java 25 and a compatible Gradle version remain required. No Java/JUnit
authoring API or verification-contract format changes in this release.
