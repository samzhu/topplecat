# ToppleCat 0.0.19

ToppleCat 0.0.19 讓 Java 團隊能用一次本次執行的結果判斷 Implementation Agent 的完成
宣稱：handoff 前先閱讀已選定的可執行契約，Verify 後再逐一檢視每個已選 Acceptance
Condition 的證據。這個版本收納了上一個已發布 GitHub Release（0.0.10）以來的變更，
團隊可以直接升級，不必自行重組中間的 tags。

## 先審閱已選契約，再逐一閱讀 AC 證據

`toppleCatReview` 在 handoff 前產生 reviewer-only 的 **Spec Review**，
`toppleCatVerify` 則在正式執行後產生 reviewer-only 的 **Verification Report**。
已淘汰的 `build/topplecat/reports/public/` bundle 不再產生；Implementation Agent 仍只會
取得公開 Java/JUnit contract 與安全的 `agent-feedback.json`。

Verification Report 會在每個已選 AC 下呈現 Public Acceptance、Hidden Tests、Expected
Result Check、Property-Based Testing 與 Mutation Testing。Contract Integrity 只會作為下游
工作的前提呈現一次。兩份 reviewer report 都支援 `--language zh-TW`；只翻譯
ToppleCat 自己的呈現內容。

## 看見 AC 沒有偵測到的暫時正式程式改動

Mutation Testing 會跟隨已選 Delivery Scope。每一個未改動的公開 Acceptance Method 都必須
偵測到精確歸因給自己 AC 的每個 mutation；一個 AC 不能因為另一個 Acceptance Method
偵測到同一改動而取得 credit。

若 AC 有未偵測到的改動，報表會先顯示已偵測與未偵測的數量，並只展開未偵測的改動。每張
reviewer-only 卡片說明 PIT 改了什麼、可取得的正式原始碼位置，以及該 AC 的公開驗收仍然
通過。只有 PIT 描述與唯一的原始碼行足以支持時，才會顯示確切的前後替換；否則報表會保留
PIT 描述，並清楚說明無法取得確切的 source-level replacement。這個 fallback 現在同時保持
有效的 HTML 與忠實的 evidence。

PIT outcome、selector、原始碼座標與其他技術診斷仍提供給 Reviewer，但絕不進入安全的
agent feedback。

## 保留可審閱的 Property 產生輸入證據

Property-Based Testing 會把每一個被捨棄的 generator input 保留為本次 JSON evidence，並在
Verification Report 分頁呈現。公開 Acceptance Method 與 Property 使用具商務意義的 JUnit
`@DisplayName`，公開 Stage Step 使用 `@As` 句子，因此 contract 描述的是商務情境，而不是
實作細節。

## 從 0.0.10 升級

1. 將 Gradle plugin 與 `topplecat-junit` dependency 更新為 `0.0.19`。
2. 停止發佈或解析 `reports/public`；改用 reviewer-only 的 Spec Review 與 Verification
   Report。讀取 report 的 tooling 必須使用 `topplecat.review-view.v7` 與
   `topplecat.verification-view.v9`。
3. 移除 `mutationTesting { threshold.set(...) }`。每個已歸因 mutation 都必須由自己的公開
   Acceptance Method 偵測；百分比設定不能取代這條規則。
4. 使用 `--spec` 時，請選取一個 test class 中全部的公開 Acceptance Method，或在正式
   Verify 前把已選方法移到專屬 class。
5. 為公開 Acceptance Method 與 Property 加上有意義的 JUnit `@DisplayName`，並為公開
   Stage Step 加上 `@As` 句子。Restore reviewer custody 後，依序執行 Check、Review 與
   Reseal，再做正式 Verify。

## 環境需求與相容性

Java 25 與既有相容的 Gradle、JUnit 需求不變。正式 Verify 仍在內部管理 PIT 1.25.5，
reviewer bundles 維持離線。ToppleCat 不提供舊 report projection 的相容 reader 或 dual
writer。

## 完整變更

上一個已發布 GitHub Release 是 0.0.10。0.0.11 到 0.0.18 的 tags 沒有發布成 GitHub
Releases，因此這份比較也包含它們的 review-report、evidence、authoring boundary 與
localization 變更。
