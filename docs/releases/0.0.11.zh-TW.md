# ToppleCat 0.0.11

0.0.11 只保留兩份清楚的人類報告：交付前閱讀完整規格的 Spec Review，以及正式
Verify 後把問題放在最前面的 Verification Report。產生的 HTML 不再與 Java/JUnit
契約爭奪事實來源，也不會讓真正的驗證發現埋在報告操作裡。

## 升級：停止使用已移除的 public HTML

ToppleCat 不再產生 `build/topplecat/reports/public/`。正式發布報告時，也會清除這個
固定產生路徑中的舊 bundle。實作 agent 繼續取得原始公開契約與安全的
`agent-feedback.json`；沒有替代的 public HTML。

直接使用 `SpecView` projection 或其 report JSON／writer methods 的程式必須移除該
整合。自行讀取 reviewer report `data.json` 的工具，必須改用
`topplecat.review-view.v7` 與 `topplecat.verification-view.v9`。本版不提供舊報告
projection 的相容 reader 或 dual writer。

除此之外，公開 Java/JUnit 驗收撰寫 API、Gradle task 名稱、`--spec` 選取方式、六個
Gate 名稱、整體判定與 machine evidence schema 都沒有改變。

## 交付前閱讀完整的已選 Spec

`toppleCatReview --spec ...` 現在產生 **Spec Review**。它會先完整呈現每份已選
Markdown 文件，再顯示其 AC 綁定的可執行材料，包括人類可讀且有語法區分的
Given／When／Then／And、公開與審閱者 Typed Case Rows、Properties、Contract
Quality Advisories，以及完整的公開 Acceptance Method 原始碼。

離線報告支援結構化 Markdown、表格、fenced code、本機圖片、語法高亮與安全的
Mermaid 流程圖。危險的 raw HTML 與 URL 會被跳脫；無法渲染的圖或本機 asset
會留下明確 fallback，不會悄悄遺失規格內容。

Spec Review 包含審閱者案例、source path 與品質提醒，所以只提供給 reviewer。頁面
也會清楚說明規格已準備完成，但尚未執行驗證。

## 先看到真正的驗證問題

正式 Verify 現在產生 **Verification Report**。首屏先說明本次交付是通過、失敗或
證據不完整，再由 Problems Summary 連到相關 Gate、AC、case、Property、mutation
發現或 integrity detail。

Contract Integrity、Public Acceptance 與 Expected Consumption、Hidden Tests、
Property-Based Testing、Mutation Testing 維持各自獨立的區塊，不建立綜合分數。
案例失敗時，預設打開第一個真正的失敗，不會先選到通過的公開案例。

當 `ToppleCase.verify(...)` 比較出不同的 JSON，審閱者報告會依欄位路徑呈現 missing、
unexpected 與 changed values，包含巢狀物件與陣列。comparison 綁定實際執行中的
compiler-described Step，而且只留在 reviewer report；assertion 與 Gate 語意都不變。

## 每次交付使用同一套 managed mutation 問題

從上一個已發布的 GitHub Release 起，正式 Verify 已固定由 ToppleCat 管理 PIT 1.25.5
與 `topplecat-managed-v1` operator profile。從 0.0.8 或更早版本升級時，請移除
`mutationTesting.producerTask` 與 `mutationTesting.reportFile`。專案仍可另外執行
自己的 PIT 工作流，但不能把它當成 ToppleCat Mutation Gate 證據。

Mutation Attribution 會精確比對公開 Acceptance Method 的 class、method、overload
與參數型別。Verification Report 忠實保留 PIT 的 `status`、`detected`、mutator、
description，以及 covering／killing／succeeding selector 關係；也會顯示每個 AC 的
detection rate 與 attribution gap，不會發明 PIT status，也不會把 mutation 證據與
Hidden Tests、Properties 或 Mechanical Seal 混成一個分數。

人類降低 threshold 後，即使 Mutation Gate 通過，raw surviving mutants 仍會呈現。
Contract Quality Advisory 仍只是非阻擋的人類提醒，不會改變任何 Gate。

## 升級步驟

1. 將 Gradle plugin 與 `topplecat-junit` dependency 更新為 `0.0.11`。
2. 若專案仍設定 `mutationTesting.producerTask` 或 `mutationTesting.reportFile`，請移除。
3. 停止發布或解析 `reports/public`，並移除對舊 `SpecView` projection 的整合。
4. 將 reviewer report reader 更新為 `topplecat.review-view.v7` 與
   `topplecat.verification-view.v9`。
5. Mechanical Seal 只適用目前版本；更新後請先 Restore reviewer custody，再 Check、
   Review、Reseal，最後才 Verify。

## 環境需求

Java 25 與既有相容的 Gradle、JUnit 需求沒有改變。正式 Verify 仍在內部管理
PIT 1.25.5。報告完全離線，不會從 CDN 載入 Mermaid、syntax highlighting、字型、
analytics 或 UI 程式。

Advisory 與 managed PIT profile。
