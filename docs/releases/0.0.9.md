# ToppleCat 0.0.9

0.0.9 gives reviewers exact Mutation Attribution for each public Acceptance
Method and adds non-blocking contract-quality prompts without letting either
projection invent a business rule.

## Credit mutation detection to the method that supplied it

Suppose both a coupon Acceptance Method and an empty-cart Acceptance Method
execute changed production code, but only the coupon method makes JUnit fail.
ToppleCat now credits detection only to the coupon AC. It reads PIT's complete
`coveringTests`, `killingTests`, and `succeedingTests` matrix, matches the fully
qualified Java class, method, overload, and parameter types, and calculates
each AC's detection rate from that exact method's coverage and kills.

PIT's official `status` and `detected` values remain unmodified reviewer
evidence; ToppleCat does not translate them into a second status-to-score
table. A usable matrix with no exact public attribution fails the Mutation
Gate. Individual unattributed mutants beside valid attribution remain reviewer
evidence and do not directly affect the Gate. Missing, malformed,
zero-mutant, or interrupted producer evidence remains `INCOMPLETE`.

Formal Verify now tracks the PIT report as input and forces both the producer
and Mutation Gate to create current-run evidence. A previous Gradle output or
cache entry cannot silently replace this run's mutation result.

## Review expected-output risks without changing the contract

Direct `toppleCatCheck` and Contract Review can flag two reviewer-only risks:
a hidden expected-output shape that matches no public variant, and likely
opaque `Id`, `Key`, or `Token` literals that vary across every public and
hidden row. This Contract Quality Advisory shows only the AC, expected path,
counts, and rule code.

The advisory is a human review prompt, not a business-rule inference. It never
changes the executable contract, Mechanical Seal, Verify evidence, Public
Spec, safe agent feedback, or a Gate.

## Upgrade

Update the Gradle plugin and `topplecat-junit` dependency to `0.0.9`. The public
Java/JUnit acceptance-authoring API is unchanged.

Custom Mutation Testing producers must emit PIT's full mutation matrix,
including `coveringTests`, `killingTests`, and `succeedingTests`, with selectors
that identify the complete Acceptance Method signature. Reviewer tooling that
reads generated projections must adapt to the direct
`topplecat.mutation-results.v1` fields, `topplecat.review-view.v6`, and
`topplecat.verification-view.v8`; there is no migration or dual-format reader.

The Mechanical Seal is current-version-only. After changing ToppleCat
coordinates, Restore reviewer custody, Check, Review, and Reseal before Verify.

## Requirements

Java 25 and the existing compatible Gradle and JUnit requirements are
unchanged.
