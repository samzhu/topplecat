# ToppleCat 0.0.5

> Review the contract more easily before handoff, and try the samples directly
> from a fresh checkout.

## Why upgrade

- The reviewer contract page now puts each acceptance condition beside the
  exact canonical test method that JUnit will execute. Public examples appear
  first; independent reviewer-only checks are clearly labelled. The page also
  has stronger contrast for practical review sessions.
- The JUnit and Spring Boot samples can now be tried from their own directories
  with `./gradlew`. Normal interactive use resolves the released package; the
  repository demos use Maven Local only when they deliberately test the source
  checkout.
- The new FAQ explains the Java/JUnit contract approach, why ToppleCat does not
  require Cucumber or `.feature` files, and how PIT, BDD, and JGiven relate to
  the project.

## Upgrade

Most projects only need to update the plugin and `topplecat-junit` dependency
to `0.0.5`.

```kotlin
id("io.github.samzhu.topplecat") version "0.0.5"
```

## Compatibility

No user-visible breaking changes. Existing contracts, reviewer custody, and
verification gates keep their behavior.
