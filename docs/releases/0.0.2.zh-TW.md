# ToppleCat 0.0.2

發佈日期：2026-07-25。

ToppleCat 0.0.2 強化驗證閘門中用來判斷 AI agent「已完成」宣稱是否成立的
核心部分。本版沒有加入另一套 authoring language，也沒有把產品範圍擴張到
Java/JUnit 委派驗證以外。

## 狀態與相容性

`0.0.2` libraries 與 Gradle plugin 已使用 `io.github.samzhu.topplecat`
座標發佈；其歷史安裝座標為 `0.0.2`。

本版使用 Java 25 開發，並以 repository 的 Gradle 9.1.0 wrapper 驗證。
ToppleCat 仍是 pre-1.0。本版沒有變更公開的 `evidence.json` 或
`agent-feedback.json` schema。

## Expected Value 正確性

每個頂層 `expected` key 都是 assertion obligation。只有
`ToppleCase.verify(...)` 能完成它。透過 `ToppleCase.expected(...)`
讀取只會記錄為 `READ`，不是 `ASSERTED`；完全沒碰到則是 `UNTOUCHED`。
啟用 expected-consumption enforcement 時，兩種狀態都會在 test invocation
返回後使該 case 失敗。

因此，測試只把 expected value 反序列化、卻沒有與 production behavior
比較時，不會再看起來像真的完成驗證。

## JSON 數值正確性

`ToppleCase.verify(...)` 現在會遞迴地依精確數學值比較 JSON number。
因此 `200`、`200.0` 與 `200.00` 彼此相等，巢狀 object 與 array 內也一樣。

這是精確比較，不是 epsilon 或浮點容忍值。不同數值、不同 object/array
結構，以及 number 與看似數字的 text 仍會失敗。

## Reviewer Escrow 更新

授權 reviewer 現在可用以下明確的 custody 流程演進已隱藏的 reviewer suite：

```text
toppleCatRestore
    -> edit src/hiddenTest
    -> toppleCatCheck
    -> toppleCatReview
    -> reviewer accepts the review
    -> toppleCatUpdateEscrow
```

`toppleCatUpdateEscrow` 會驗證並暫存完整的新版 source set、寫入只含變更
數量而不含 reviewer 內容的本機 audit metadata、在啟用前保留舊的 active
custody state，並於驗證或啟用失敗時安全復原。啟用時會在 filesystem 支援的
情況下要求 atomic move；不支援時仍使用相同的驗證與復原路徑。一般
`toppleCatHide` 仍會拒絕未經審閱的 restored source 變更。

## Public Contract Mutation 範圍

預設 PIT producer 現在明確限制為 `sourceSets.test`，也就是 public test
classes 與 public case rows。Reviewer rows 與 reviewer-only JUnit tests
仍是獨立的 hidden-retest safeguard，不能灌高 public mutation score。

因此 score 的意義很清楚：若某個 boundary 必須殺死 mutant，它就應屬於
public executable contract。ToppleCat 仍不產生 per-case mutation score，
也不推斷 custom producer 的範圍。

## 可信的終止訊號

Aggregate verdict 為 `FAIL` 或 `INCOMPLETE` 時，`toppleCatReport`（因此也
包括 `toppleCatVerify`）現在會讓 Gradle build 失敗。Evidence、安全的
agent feedback、HTML reports、stable copies 與 archived run 會先完整寫出，
之後才回報失敗；`toppleCatRehide` 仍會以 finalizer 執行。

Public 與 reviewer verification test tasks 每次驗證都會重新執行，不會把
Gradle up-to-date 或 build cache 的結果冒充本次證據。最終綠燈現在代表
aggregate `PASS`；明確設為 `DISABLED` 的 safeguard 保留原有 aggregate
語意。

## 範圍

本版沒有新增第二套 DSL、CLI、Spec Kit integration、更豐富的 agent
diagnostics、per-case mutation scoring、remote reviewer custody 或 artifact
attestation。這些都不屬於 0.0.2 的正確性修正範圍。

## 驗證

最終 release tree 已通過：

- correctness、exit signal、reviewer custody 與 configuration cache 的
  targeted regression tests；
- `./gradlew check`；以及
- `GRADLE_CMD=./gradlew scripts/verify-release.sh`，包括兩套獨立 sample
  workflows、mutation-gate integration、文件與 skill validation，以及
  public artifact privacy checks。
