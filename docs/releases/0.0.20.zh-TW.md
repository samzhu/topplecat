# ToppleCat 0.0.20

ToppleCat 0.0.20 讓驗證報告能以單一驗收條件為單位閱讀，審閱者不用先理解工具術語，也能看出實際出了什麼問題。

## 每個 AC 都用固定順序閱讀

以 AC 為主的驗證報告現在會在每張 AC 卡片中固定保留 Public Acceptance、Hidden Tests、Expected Result Check、Property-Based Testing 與 Mutation Testing。問題摘要會直接連到受影響的 AC；技術證據則留作稽核，不會干擾主要閱讀順序。

Property-Based Testing 現在會說明：要求多少個產生輸入、實際完成多少個、捨棄多少個，以及反例是否讓執行提早停止。因此像 `12 of 200` 這樣的結果，審閱者也能理解它代表什麼。

## 公開驗收失敗後，Mutation Testing 不再誤導

Mutation Testing 現在需要先有通過的 Public Acceptance baseline。若公開案例已失敗，Mutation Testing 的結果會是 `INCOMPLETE`，不會誤稱它已判斷出暫時變更正式程式行為是否被偵測到。Hidden Tests 與 Property-Based Testing 仍會各自保留獨立的本次執行證據。

## 升級

將 Gradle plugin 與 `topplecat-junit` dependency 更新為 `0.0.20`。不需要遷移原始碼。

## 環境需求

仍需要 Java 25 與相容的 Gradle 版本。
