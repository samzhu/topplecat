# ToppleCat 0.0.26

ToppleCat 0.0.26 讓 Reviewer 能從完整選取的 Spec，一路讀到針對 agent 完成宣稱的正式證據；
同時清楚區分快速的功能範圍驗證，與 CI 使用的完整專案判定。本版彙整自上一個已發布的
GitHub Release `0.0.10` 以來所有已標記的變更。

## 先讀完整契約，再讀真正重要的證據

交付前，`toppleCatReview --spec ...` 會呈現完整選取的 Markdown Spec，以及其 Java
Scenario、公開與 reviewer 持有的型別化案例列、Properties 和公開 Acceptance Method 原始碼。
正式 Verify 後，僅供 Reviewer 閱讀的 Verification Report 會先呈現本次結果，再讓人只展開
需要的 Acceptance Condition、預期值／實際值比較或技術證據。

兩種報告都支援 invocation-only 的 `--language en` 與 `--language zh-TW`。只有
ToppleCat 自己的呈現文字會被在地化；作者撰寫的契約文字、producer 術語、evidence、Gate 與
verdict 均保持原樣。

## 快速驗證一個功能，不削弱整個專案的封印

不帶選取條件的 `toppleCatVerify` 仍是 CI 使用的完整專案指令。Reviewer 現在可用重複的
Spec 路徑或重複的 AC ID 為完成的功能取得快速正式證據，但兩種不能混用：

```bash
./gradlew toppleCatVerify --spec specs/checkout/spec.md
./gradlew toppleCatVerify --ac AC-CHECKOUT-THRESHOLD --ac AC-CHECKOUT-VIP
```

選取的執行只會對這些 AC 執行公開驗收、Hidden Tests、Property-Based Testing 與 Mutation
Testing。它的 `PASS` 會明說不代表完整可執行契約通過。Contract Integrity、`toppleCatSeal`
與 `toppleCatReseal` 永遠使用完整契約與驗證政策；Seal 和 Reseal 會拒絕 `--spec`、`--ac`。

## 用五種驗證手段解釋產品，不混淆它們的角色

公開產品頁現在清楚呈現五種合成的 checkout 示範：Public Acceptance、Hidden Tests、
Property-Based Testing、Mutation Testing 與 Contract Integrity。每張卡都使用完全合成的報告
摘錄，並說明觀察到的結果支持什麼、不能證明什麼。

Expected Consumption 仍是公開驗收內必須確認「預期輸出確實被 assertion」的檢查；它不再被
呈現成第六種、平行的測試手段。公開產品頁仍與實際交付的 evidence 及 implementation-agent
handoff 完全分離。

## 從 0.0.10 升級

1. 將 Gradle plugin 與 `topplecat-junit` dependency 更新為 `0.0.26`。
2. 停止發布或解析已退役的 `build/topplecat/reports/public/` bundle，並移除對已退役
   `SpecView` projection 的整合。讀取報告 JSON 的 reviewer tooling 必須使用
   `topplecat.review-view.v7` 與 `topplecat.verification-view.v10`；不提供相容 reader 或
   雙重 writer。
3. 移除 `mutationTesting { threshold.set(...) }`。每個公開 Acceptance Method 都必須偵測到
   精確歸屬於其 AC 的每一個 mutation。
4. CI 請使用未帶 `--spec` 或 `--ac` 的 `toppleCatVerify`。本機要執行範圍驗證時，請選擇
   Spec 路徑或重複 AC ID 其中一種。不要將 `--spec`、`--ac` 或 `--language` 傳給 Seal 或
   Reseal。
5. 正式 Verify 前請先 restore reviewer custody，接著依序執行 Check、Review、Reseal。
   Mechanical Seal 與 custody format 只適用於目前版本。

## 環境需求

仍需要 Java 25 與相容的 Gradle。正式 Verify 會在內部管理 PIT 1.25.5；報告 bundle 維持
離線且 CSP-safe。公開 Java/JUnit acceptance-authoring API 不變。
