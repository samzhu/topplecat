# ToppleCat 0.0.10

0.0.10 makes formal Mutation Testing comparable across AI deliveries: every
Verify run now owns the PIT version, operator set, public Acceptance Methods,
and full result matrix while preserving the producer's raw evidence for human
review.

## Upgrade: remove custom formal mutation producers

Formal `toppleCatVerify` no longer accepts `mutationTesting.producerTask` or
`mutationTesting.reportFile`. Remove those settings before upgrading. A project
may still run its own PIT workflow separately, but ToppleCat does not read,
merge, or use that result for its Mutation Gate.

The public Java/JUnit acceptance-authoring API is otherwise unchanged.

## Run the same mutation challenge for every delivery

Formal Verify now runs PIT 1.25.5 with the versioned
`topplecat-managed-v1` profile. The profile explicitly selects return-value,
forced-conditional, conditional-boundary, void-call, and arithmetic operators;
it never inherits PIT's `DEFAULTS`, `STRONGER`, or `ALL` groups.

The producer is fresh for every formal run and targets only compiler-emitted
public Acceptance Methods. Hidden Tests, Properties, helpers, and a project's
own PIT tasks cannot contribute mutation coverage or detection credit.

## See which exact Acceptance Method detected a change

ToppleCat keeps PIT's original `status`, `detected`, mutator, description,
`coveringTests`, `killingTests`, and `succeedingTests`. Mutation Attribution
matches the complete class, method, overload, and parameter types. Each AC's
detection rate therefore counts only mutants covered by that Acceptance Method
and killed by that same method.

A usable matrix with no exact public attribution fails the Mutation Gate. Once
some exact attribution exists, remaining unattributed mutants and ACs with no
covered managed-profile mutant stay visible to the reviewer without directly
changing the Gate. The sealed threshold still applies to every AC that has
covered mutants; lowering it remains a human verification-policy decision.

## Review independent evidence without a blended score

Verification HTML presents Mechanical Seal, Hidden Tests, Property-Based
Testing, and Mutation Testing as separate sections. Mutation details include
the managed profile, operator summaries, per-AC rates, attribution gaps, and
expandable raw PIT relationships. Every enabled Independent Safeguard finishes
and retains its own current-run result even when another one fails.

Contract Review also includes the reviewer-only, non-blocking Contract Quality
Advisory introduced since the previous published GitHub Release. It flags
possible expected-shape drift or opaque identifier literals for human review;
it never infers business rules or affects a Gate.

Public reports and `agent-feedback.json` remain safe: profile details, raw PIT
fields, selectors, classes, methods, counts, hidden data, and private failures
stay reviewer-only.

## Upgrade actions

1. Update the Gradle plugin and `topplecat-junit` dependency to `0.0.10`.
2. Remove `producerTask` and `reportFile` from `mutationTesting` configuration.
3. Restore reviewer custody, Check, Review, and Reseal before Verify because
   the Mechanical Seal is current-version-only.

Reviewer tooling that reads generated projections must adapt to the directly
updated `topplecat.mutation-results.v1` managed-profile fields and the current
`topplecat.review-view.v6` and `topplecat.verification-view.v8` projections.
There is no migration or dual-format reader.

## Requirements

Java 25 and the existing compatible Gradle and JUnit requirements are
unchanged. PIT 1.25.5 is managed internally by formal Verify.
