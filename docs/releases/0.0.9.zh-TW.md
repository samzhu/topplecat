# ToppleCat 0.0.9

0.0.9 讓審閱者看見每個公開 Acceptance Method 的精確突變歸因，也加入非阻擋的
契約品質提醒；兩者都不會替人類推測業務規則。

## 只把 mutant detection 算給真正提供證據的方法

假設優惠券與空購物車兩個 Acceptance Method 都執行到被改壞的正式程式，但只有優惠券
方法讓 JUnit 失敗。ToppleCat 現在只把 detection 算給優惠券 AC。它讀取 PIT 完整的
`coveringTests`、`killingTests` 與 `succeedingTests` 矩陣，精確比對 Java 完整 class、
method、overload 與參數型別，再以同一方法的 coverage 和 kill 計算每個 AC 的
detection rate。

PIT 官方的 `status` 與 `detected` 值會原樣保留在 reviewer evidence；ToppleCat 不會
另建一份 status-to-score 對照表。可用矩陣若完全無法精確歸因到任何公開方法，
Mutation Gate 會失敗。已有有效歸因時，其餘 unattributed mutants 只保留在 reviewer
evidence，不直接影響 Gate。producer 證據缺失、損壞、零 mutant 或執行中斷時，仍為
`INCOMPLETE`。

正式 Verify 現在會追蹤 PIT report 輸入，並強制 producer 與 Mutation Gate 產生本次執行
證據。先前的 Gradle output 或 cache 不會默默取代這次的 mutation result。

## 檢查 expected output 風險，但不改寫契約

直接執行 `toppleCatCheck` 與 Contract Review 時，可能看到兩類 reviewer-only 提醒：
隱藏 expected output shape 不符合任何公開 variant，以及疑似 opaque 的 `Id`、`Key` 或
`Token` literal 在每個公開與隱藏案例都不同。Contract Quality Advisory 只顯示 AC、
expected path、計數與規則代號。

這是給人類的契約品質提醒，不是業務規則推論。它不會改變可執行契約、Mechanical
Seal、Verify evidence、Public Spec、給 agent 的安全回饋或任何 Gate。

## 升級

將 Gradle plugin 與 `topplecat-junit` dependency 更新為 `0.0.9`。公開 Java/JUnit
驗收撰寫 API 沒有改變。

自訂 Mutation Testing producer 必須輸出 PIT 完整 mutation matrix，包含
`coveringTests`、`killingTests` 與 `succeedingTests`，selector 也必須識別完整的
Acceptance Method signature。若 reviewer tooling 會讀取產生的投影，必須配合直接更新的
`topplecat.mutation-results.v1` 欄位、`topplecat.review-view.v6` 與
`topplecat.verification-view.v8`；本版不提供 migration 或雙格式 reader。

Mechanical Seal 僅適用目前版本。更新 ToppleCat 座標後，請先 Restore reviewer custody，
再 Check、Review、Reseal，最後才 Verify。

## 環境需求

Java 25 與既有相容的 Gradle、JUnit 需求沒有改變。
