# ToppleCat 0.2.1

ToppleCat 0.2.1 讓 Java/JUnit 團隊可以把完整的 canonical Markdown 與確切的可執行驗收
投影放在同一份 Spec Review 裡閱讀，因此交接不再依賴會漂移的第二份 locator 檔案。

## 在業務上下文旁閱讀可執行契約

Spec Review 會完整呈現每一份選定的 Markdown 文件一次，並在作者放置的獨立 marker 位置
嵌入該 Acceptance Condition 已檢查的 Java/JUnit projection。人或 upstream workflow 提供
一個或多個確切的 repository-relative `.md` 路徑；同一組重複的 `--spec` 路徑會傳給 Check、
Review 與 scoped Verify。CommonMark heading、marker、一般引用、作者格式、source snapshot、
巢狀案例值、可存取的 disclosure，以及 public/reviewer custody 都會保留，不改變可執行契約。

## 移除選取漂移與不安全 fallback

舊的 `topplecat-specs.json` locator、stable Spec key、AC inventory mirror 與 Python 維護 helper
已移除。`.feature` 檔案不會被讀取、登記或翻譯。selected 失敗時會停止，不會默默 fallback 到
whole-contract；沒有 selection 時，Check、Seal、Verify 仍可維護完整契約，但 Review 必須有
`--spec`，也不會宣稱 whole-contract 已 ready for Review。Review 之後仍使用
`toppleCatSeal` 封存完整可執行契約；這次 release 不改變 Gate、Evidence 或 custody 的意義。

## 拒絕不一致或不安全的 checked input

產品 CommonMark parser 是 heading/marker 結構與聚合 source diagnostics 的唯一權威。selected
路徑會拒絕 absolute、traversal 與 symbolic-link 輸入。Check 與 Review 共用不可變的 checked
文件、Java source 與本機 asset bytes；選取失敗後會清除過期 selected handoff，Review 也會拒絕
Check 後被修改的 asset 或 source。

## 在網頁或離線環境閱讀大型報告

Review navigation 會把一般 AC reference 導向唯一 projection；作者連結與 inline code 維持
原樣，並保留鍵盤、螢幕閱讀器、英文、繁體中文、窄視窗、raw HTML 安全性與大型報告行為。
公開網站與學習範例也同步說明這套 selected-Spec workflow。

## 要求與升級動作

ToppleCat 執行需要 JDK 21 或 25；使用端 source 可以 target Java 17、21 或 25，但 Gradle
執行環境必須是支援的 JDK。這個 release line 尚未發布到 Maven Central，因此請先執行
`./gradlew publishToMavenLocal`，並把 `mavenLocal()` 放在 `mavenCentral()` 前面，直到維護者
完成發布。既有使用者必須把舊 locator workflow 改成重複傳入 repository-relative `--spec`
路徑，並讓 Review 明確帶 selection。
