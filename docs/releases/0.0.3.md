# ToppleCat 0.0.3

## Approved-contract integrity

0.0.3 closes a verification-integrity gap: a delegated implementation could
previously change the visible executable contract along with production code,
then make public tests, hidden retests, expected-value checks, and mutation
testing appear green against that altered contract.

Hide now creates a version-2 escrow epoch that includes reviewer approval of:

- exact public test-source and typed case-data bytes;
- relevant project-local Gradle build logic;
- a public semantic `ContractDefinition` digest; and
- the resolved hidden-retest, expected-consumption, and mutation policy.

`toppleCatVerify` adds the mandatory first evidence gate:

```text
CONTRACT_INTEGRITY
JUNIT
REVIEWER_JUNIT
EXPECTED_CONSUMPTION
MUTATION
```

The comparison is fresh and run-scoped. On a mismatch it reports
`CONTRACT_INTEGRITY: FAIL`, does not run downstream verification as final proof,
records those four gates as `INCOMPLETE`, writes safe feedback and evidence,
removes a stale public Spec bundle, re-hides reviewer source, and exits nonzero.
Missing or legacy approval produces `INCOMPLETE`, never an unsealed PASS.

## Intentional evolution and migration

Ordinary Hide, Restore, Rehide, and Verify preserve the existing approval. An
authorized reviewer must use this sequence to approve a public-contract,
policy, or reviewer-suite change:

```text
toppleCatRestore
    -> edit
    -> toppleCatCheck
    -> toppleCatReview
    -> reviewer accepts the review
    -> toppleCatUpdateEscrow
```

`toppleCatUpdateEscrow` atomically activates the revised hidden inventory and
approval. Existing v1 escrow remains readable for Restore and Rehide, but its
first verification is `INCOMPLETE` until that explicit reseal migrates it to v2.

`evidence.json` and `agent-feedback.json` keep schema version 1; the generic
gate list now includes `CONTRACT_INTEGRITY`. Safe feedback never exposes
approval digests, paths, policy values, ACs, case data, or reviewer details.
