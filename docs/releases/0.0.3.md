# ToppleCat 0.0.3

## Highlights

- ToppleCat now remembers the public contract a reviewer approved. If public
  tests, case data, relevant Gradle logic, or verification settings change
  afterward, `toppleCatVerify` fails with `CONTRACT_INTEGRITY: FAIL`. An agent
  cannot weaken the test to match its implementation and still get a PASS.

- Reviewer source and approval data now live outside the repository at
  `~/.topplecat/projects/<project-key>/escrow/`. A copied or freshly cloned
  project cannot accidentally reuse that reviewer state or create a new
  approval from public files.

- Legacy project-local escrow is migrated explicitly with
  `./gradlew toppleCatMigrateEscrow`. ToppleCat checks the stored reviewer files
  first; a damaged escrow stays in place, and concurrent migrations do not
  remove active reviewer state.

## Upgrade note

If you use `.topplecat/escrow/` from an earlier version, run:

```bash
./gradlew toppleCatMigrateEscrow
```

Old v1 escrow still needs an authorized reviewer to Restore, Check, Review, and
run `toppleCatUpdateEscrow` before it can produce a PASS. See the
[verification guide](../guide/verification-and-evidence.md) for that workflow.

If your CI parses ToppleCat's JSON reports, it will now see an additional
`CONTRACT_INTEGRITY` check. Most users do not need to change anything.

## Boundary

Reviewer-local escrow is local storage, not a sandbox. Run Verify in a trusted
reviewer or CI environment and give the implementation agent only a public
checkout plus safe feedback.
